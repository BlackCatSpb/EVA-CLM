**Почему спайки вообще возможны (неклассическая природа).** В классическом
трансформере градиент идёт по identity-резидуалу, а голова — линейная проекция +
softmax: градиент (p−y) ограничен и гладок, «спайков по построению» нет (его
инстабильности — от lr/данных/attention-логитов). В EVA:
- голова: sigmoid-кодированные биты (лог-оддсы через сигмоиду — насыщается,
  производная →0 на краях), кодбук (дискретно-подобные коды, ST-путь), лакуна,
  temper/emphasis, SRL, фантомный канал — при уходе битов в край градиент
  КОНЦЕНТРИРУЕТСЯ в немногих не-насыщенных путях (отсюда `g_logit_to_hidden`
  5790 против None в норме);
- ствол: зеркала/мост (кросс-слойные EMA), bind (фазовая спираль — мультипликатив),
  VSA-суперпозиции, обучаемая τ-лестница, гейты зрелости (закрываясь, обнуляют
  градиентные пути и перенаправляют поток), банк памяти, дискретные рождения UCL;
- лоссы: ветки + балансер со спектральным выравниванием + kill-switch'и + safety-путь.

Вывод: сатурация головы — **штатный режим** архитектуры, а не сбой; поэтому и есть
стена, гашение ~55 шагов и затухание интенсивности по мере устаканивания битов.
Классическому LLM такой режим нечем воспроизвести.

раньше было 8.6–8.8, теперь 13.0–13.5. Тренировочный CE при этом **улучшается**

**Интерпретация.** EVA — метакогнитивная архитектура с саморегуляцией
(LossBalancer, safety-стена, LR-контроллер, DepthController, зеркала), и вся её
история — это поглощение возмущений с последующей стабилизацией: спайки 495/1430/

саморегуляция — часть архитектуры.

## Bind: state-level attention — что можно улучшить (мысль, 2026-09-20)

Bind — это ассоциативное внимание **на уровне состояний**: связал фазовой спиралью →
прочитал по резонансу. В коде уже есть: golden-схема частот (`bind_twist_scheme`),
4 шкалы (`bind_twist_S`), twist-gate, QK-norm (`bind_qk_norm`), выход `coherence`
(фазовое согласие). Но сейчас механизм спит: градиенты bind-проекций крошечные
(`g_wq` 1.9e-5, `g_wk` 4.5e-6…2e-3), `w_m2v` (зеркало→VSA) 0.22→0.011, CARRY=0.
Причина: на горизонте 512 кэш точнее, а ассоциативная дальность задачей
(next-token на прозе) не оплачивается.

Кандидаты улучшений (по возрастанию вмешательства):
1. **Явная супервизия** bind/unbind round-trip (связал→развязал→восстановил) —
   сейчас bind учится только сквозь CE, сигнал тонет; `coherence` уже считается,
   может служить целью.
2. **Cleanup**: SRL как мягкое итеративное разрешение состояний (сейчас диагностика,
   `apply` opt-in; на 1045 hard-refine разносил — только мягкая версия с каденсом).
3. **Запросная сторона**: `g_wq` почти ноль — query-проекции не учатся; им может
   помочь свой lr-путь (как readout-разморозка M64.7) или multi-scale queries.
4. **Структура**: learnable twist-частоты per-scale (golden фиксирован), тюнинг
   `code_sparsity`/K против кросс-тока.
5. **Источники ключей**: ключи из банка/sentence-ring — кросс-механизменная
   ассоциация, роль, которой у кэша нет (content-addressable vs recency).

Условие осмысленности: улучшать bind только вместе с оплачиваемой ролью — дальность
>512 (удлинение τ-лестницы), данные/задача с ассоциацией, или явная супервизия (п.1).

## Дальность VSA: 512 — не ёмкость, а выбор τ (мысль, 2026-09-20)

**Уточнение природы 512.** 512 — не предел механики VSA, а самый медленный τ лестницы
(`VSA_LADDER = (8, 32, 128, 512)` — жёсткая константа в `core/tau_api.py`; `tau_max` —
конфиг). Забывание = e^(−t/τ); горизонт задаёт τ. При τ→∞ горизонт = длине
последовательности — ценой кросс-тока (интерференция суперпозиции: D=2560 → ~10³
элементов до деградации чтения).

**Горизонт уже эмерджентный — и модель его сжала.** `_tau_l_dev` (обучаемые отклонения,
T9.4) дали выученный диапазон 6.65…230 против канонов 8…512: модель выбрала короче,
потому что задача (next-token на прозе) не требует дальше. Если бы требовала — лестница
бы удлинилась.

**Что даст «кратность любой длине»:**
1. Расширение лестницы: `VSA_LADDER = (8,32,128,512,2048)` + `tau_max=2048` (одна
   строка + конфиг) — обучаемые отклонения работают на новых шкалах (или сжимают их).
2. Иерархическая рекурсия: биндить чанковые саммари (512-блоки → связанные
   представления → уровень выше) — горизонт умножается (512×512 на 2 уровнях,
   лог-глубина для любой длины). Механизма нет (уровни банка есть, VSA-рекурсии нет).
3. Golden-фазы (`bind_twist_scheme='golden'`) задуманы под длинные горизонты
   (минимальная резонансность, слабый алиасинг; float32 ≈ 10⁴ позиций) — но τ-потолок
   512 связывает раньше алиасинга.

**Ограничение:** кросс-ток — дальний горизонт = образ (мало значимых элементов), не
вербатим.

**Дешёвая проверка:** A/B лестницы (8,32,128,512,2048) + `tau_max=2048`: сожмёт ли

## Cross-scale attention (мысль, 2026-09-20)

**Идея (оператор):** прямое внимание между τ-шкалами (τ1↔τ2↔τ3↔τ4) на уровне
состояний — не горизонт, а связывание самих масштабов.

**Сейчас:** шкалы взаимодействуют только косвенно — суперпозицией
(`bind = Σₛ Wₒ·(u'ₛ ⊙ v'ₛ)`, параллельно), `hybrid_alpha` (0.3–0.7) и зеркальным
fast/slow (2 скорости, не 4 шкалы). Прямого scale-to-scale чтения нет.

**Эскиз:** per-scale состояния `u_s` (S=4) → attention: `q_s=W_q u_s`, `k_t=W_k u_t`,
softmax по t → `u'_s=Σ_t a_st v_t`; стоимость S²=16 пар/токен — крошечная; параметры
общие + per-scale норм. Дешевле: пирамида (coarse из fine пулинга + broadcast) или
обучаемая S×S матрица смешивания.

**Оценка:** архитектурно здраво (известный multi-scale coupling, у нас отсутствует);
ортогонально bind (bind — внутри шкалы: фазовая спираль/coherence; cross-scale —
между); можно совместить (смешать масштабы → связать). Риск: плотность блока, новые
градиенты. Ценность зависит от задачи: для языка мультимасштабная структура
(токен/фраза/тема) реальна, но выученная τ-лестница сжалась — модель пока не ищет
дальние масштабы. Проверка: маленький A/B-арм (~S²·d параметров), вклад в val +
`alpha_std`/τ-диапазон.

## Доверить ли бюджет кэша модели (мысль, 2026-09-20)

**Уже отдано:** M34-кольцо само выбирает, ЧТО держать (retention = novelty·exp(−age/τ),
не FIFO); τ-лестница обучаемая (шкалы — выбор модели, 6.65…230); глубина — плато-детектор.
**Не отдано:** БЮДЖЕТ (горизонт 512 / max_entries 12).

**Почему бюджет не отдать:**
1. Цены нет в лоссе — compute/память чтения кэша не в CE → модель захочет максимум
   контекста всегда; без штрафа бюджет выбирается «в потолок», а не по потребности.
2. Стабильность: плавающий бюджет = плавающее число ключей = нестационарная цель +
   петли обратной связи (кольцо→градиенты→τ→кольцо). DepthController безопасен, потому
   что меняет структуру редко и по плато — кольцу нужен такой же каденс.
3. Сравнимость eval: val при разном горизонте — разные режимы.

**Правильная форма (связка с τ):** горизонт кэша = ВЫУЧЕННЫЙ τ_max, а не конфиг. Сейчас
`AUTO = cfg.tau_max` (512), модель выучила 230 → headroom простаивает. Привязка к
выученному τ = «модель выбирает по потребности» автоматически. Следствие: сработает в
сторону УМЕНЬШЕНИЯ (эффективность, не дальность); для дальности нужно, чтобы модель
захотела больше (задача/данные), иначе тот же lock-in, только с разрешением.

## Многоразрешающий кэш на шкалах τ (мысль, 2026-09-20)

**Идея (оператор):** записи кэша не одного размера (окно 384), а на шкалах τ-лестницы
(8/32/128/512/2048) — пулы состояний на каждой шкале; чтение = attention ПО ШКАЛАМ
(per-scale гейты) — модель сама выбирает разрешение под запрос (локальное → 8/32,
фраза → 128, тема → 512/2048). «Числа τ» становятся адресами/разрешениями памяти,
а не только временами забывания.

**Почему осмысленно:** verbatim-версия того, что VSA делает суперпозицией — точность
K/V + мультимасштаб (чего не было ни у VSA из-за кросс-тока, ни у кэша из-за одного
разрешения). Память S×K/V (low-rank) — крошечная; compute — attention по S×entries.
Стык двух идей: cross-scale attention + бюджет по τ.

**Что проверить математически:**
1. ёмкость при наращивании: пул на 2048 → сколько элементов до интерференции;
2. формирование пер-шкальных записей: пулинг (mean/learned) или байндинг, обучаемость
   сквозь CE;
3. не разъедется ли чтение: модель выберет одну шкалу и проигнорирует остальные (как с
   VSA) — тогда штраф на разнообразие чтения или явная супервизия.

**Ожидание:** модель будет читать то, что оплачивается — вероятно ближние шкалы
(8/32/128), игнорируя 2048, пока задача не потребует. Выигрыш: (i) точность на средних
масштабах, (ii) экономия, (iii) инфраструктура для дальности. Реализуемость: средняя
(новый слой кэша + cross-scale чтение, A/B против текущего).

## Ключевые решения

### 1. Per-layer maturation (коммит a735ac0)
- **Проблема:** bridge_conn collapse на uniform maturation
- **Решение:** deep layers (tau≈515) открываются быстрее (T_eff=8000), shallow (tau≈8) медленнее (T_eff=16000)
- **Формула:** `gate_l = sigmoid((t - (T0 + alpha*(1-tau_norm_l)*T_delay)) / delta_t)`
- **Результат:** bridge_conn стабилен 0.12→0.049 (нет коллапса)

### 2. SpectrumGate в bridge routing (коммит 9ad91f9)
- **Формула:** `gate = sigmoid(logits) * (1 + softmax(logits/tau))`
- **Tau:** из maturation — `effective_tau = tau_max*(1-mat) + tau_min*mat`
- **Свойство:** sigmoid сохраняет базу, softmax добавляет emphasis

### 3. HybridSigmoidSoftmaxHead (коммит 5826661)
- **Проблема:** LM head чисто sigmoid → entropy 10.5, модель "гадает"
- **Решение:** перенести SpectrumGate в `_su()` метод головы
- **Формула:** `gate = sigmoid(zt) * (1 + softmax(zt/tau))`, tau = exp(log_temp)
- **Результат:** entropy 10.5→0.58, модель фокусируется
- **Стоимость:** 0 новых параметров, hot-swap, совместим с чекпоинтами

### 4. Tau без магических чисел
- Tau всегда берётся из модели:
  - bridge: `effective_tau = tau_max*(1-mat) + tau_min*mat`
  - LM head: `tau = exp(log_temp)`
  - SpectrumGate: `tau = exp(log_tau)` (learnable)
- Принцип: **никаких внешних гиперпараметров для tau**

### 5. Поток: fuse + капы + якорь (M50/M51)
- **Проблема:** 2970 — поток ×10/слой до ~1e16, final_norm переполнен → выход 0 → транк мёртв.
- **Решение:** `_stream_cap(x, 1e3)` после каждого блока; капы инъекций веток 1e4;
  **абсолютный якорь** в branch-loss (`branch_var_anchor=0.5`) — лосс был масштабно-инвариантен.
- **Свойство:** кап масштабно-инвариантен (направление сохраняется), Jacobian на пороге O(1).

### 6. Гейт: аудит и финальная форма (M52a)
- Мёртвый `base` убран из нормированного пути; акцент читает `z/T` без `bit_bias` (corr +0.90 → 0);
  λ обучаемый (init 1); **стенка** `w·relu(|u|−6)²` (линейный барьер: 9.4e-14 → 1.9e-4 при u=30);
  ST-клампы τ (форвард тот же, градиент живой).

### 7. Лакуна: структурная + относительная новизна (M52b/M55b)
- `e_l = h − Σ z_k R_k` ортогональна readout (7e-7) — голова математически слепа к 97.5% состояния.
- Абсолютная ℓ ≈ √(1−K/D) = 0.984 **всегда** → гейт и банк читают `ℓ/EMA(ℓ)` (само-калибровка).

### 8. SRL: диагностика по умолчанию (M53/M53d/M53e)
- Аннилинг-EM по кодам; hard-refine убил прогон на 1045 (ce_raw 11→91, sat→1) → `head_srl_apply=False`
  (телеметрия концепт/противоречие/лакуна без вмешательства), каденс 50.

### 9. Концепт-системы связаны (M59)
- A) подтверждённые фантомы головы рождают концепты в UCL (`birth_from_direction`, ключ = `q_proj(d)`);
- B) активные концепты UCL ведут phantom basis головы;
- C) фантомный канал **растёт** (ёмкость 64, активные in-place, миграция чекпойнтов дотягивает).

### 10. Расписание под арифметику униграммы (M60)
- Шаг Адама ≈ lr → лог-частоты требуют ~3/lr шагов: **lr 6e-4, warmup 300** (было 3e-4/1200).
  Результат (текущий прогон): CE 7.34 → 4.3–4.9, val 8.4897@5720 (uniform 11.09, униграмма 7.48).

### 11. Вочдог удалён (M58)
- FailureDetector был полностью инертен (check() не вызывался нигде) — удалён, а не «оживлён».

### 12. Воспроизводимость (M56b)
- `torch.manual_seed(1234)` перед созданием модели: без него каждый рестарт стартовал из другой
  точки (step-0 ce_raw гулял 11.8–15.3) и A/B-армы были несравнимы.

## Философия архитектуры

- **Сигмоид** = анархия (все равны, нет фокуса)
- **Софтмакс** = диктатура (один победил, остальные мертвы)
- **Гибрид** = демократия с лидером (все участвуют, лучший ведёт)
- **Per-layer maturation** = эволюция (глубокие成熟 быстрее, shallow сохраняют gradient)
- **Bridge** = кросс-слойная коммуникация (не residual, а модуляция)

**Как читать метрики (не классический LLM).** EVA — метакогнитивная архитектура
с саморегуляцией (LossBalancer, safety-стена, LR-контроллер с зеркалом, DepthController,
гейты зрелости, фантом-банк), и её штатные режимы выглядят как «сбои» в терминах
обычного трансформера:
- спайки головы (сатурация битов) — норма, гасятся стеной за ~55 шагов;
- всплески aux/branch после резюма/открытия глубины — транзиенты адаптации;
- просадка внешней parity-оценки во время структурной перестройки — калибровка
  новых слоёв/каналов, не патология;
- LR-контроллер активно демпфирует (`mult` → 0.5, lr 6e-4 → 3e-4), давая системе
  устаканиться — это и есть механизм стабилизации.
Классические интуиции (layer-wise gradient flow, softmax-голова, «overfitting»)
здесь не применимы: голова и градиентные пути устроены принципиально иначе
(sigmoid-биты + кодбук + лакуна + SRL + фантом; зеркала/мост/bind/VSA/τ-лестница).
Смотреть на внутренние сигналы (CE, sat, conflict, балансер, LR-контроллер) как на
признак здоровья, а внешний val — как на отстающую метрику, которая возвращается
после стабилизации.

**Пер-слойная регуляция (архитектура различает участие слоёв).** Это не однородный
стек: каждый слой сам находит степень вовлечения, и спайки — побочный продукт того,
что слои ещё не разошлись по ролям (затухание 201→126→108→39.6 — это и есть процесс).
Механизмы пер-слойности:
- гейты зрелости (профиль @5720: L0–L3 0.18–0.21, L4–L5 0.88/0.84, L8–L23 0.33–0.63);
- пер-слойный LR (`per_layer_ls_lr`, `ls_mult` 0.73–0.91 из fast/slow EMA var(log_scale));
- τ-лестница (`tau_l_dev` — выученные отклонения; ladder 6.65→230) + intent-лестница;
- DepthController — ступени по 4 слоя (8→12→16→20→24);
- depthgrad — разные роли (L23 5.5e-3, L0 ~8e-5); `mlp_depth_lr_exp=0.10` (L16 ×4.5, L23 ×10);
- аномалия-трекер — пер-слойный надзор (L8 с гейтом 0.0000 «ушёл в сторону»);
- `gate_var` 0.033–0.05 — пер-слойная дисперсия гейтов.
Стабилизация = `mat`/`ls_mult`/`tau_dev` перестают двигаться, слои разошлись по ролям,
спайки прекращаются.

- **Униграмма учится арифметикой Адама**: шаг ≈ lr, лог-частоты (−3…−5) требуют ~10k шагов
  при 3e-4. M60 (6e-4 + warmup 300) сократил это вдвое: CE 7.34 → 4.4–4.8.
- **Кэш несёт поток**: гейт открылся ~770 и стоит на 1.0 (read_ratio≈1.0) — VSA-CARRY ≈ 0,
  непрерывность текста держит low-rank K/V-кольцо (горизонт 512 токенов, sentence-ring).
  Детали на 8360: `g_cache_attn`=0.23 (attention учится), но `g_cache_gate`=0 — гейт
  в насыщении (фиксированный «полностью открыт», не адаптивный). **VSA как носитель
  отключён самой моделью**: `w_m2v` (зеркало→VSA) 0.22→0.011, bind-градиенты крошечные
  (`g_wk` 4.5e-6, `g_wv` 2.3e-4), `g_l1_proj` ~5e-9 (L1-проекция мёртвая). Живы из
  VSA-контура: τ-лестница (`g_tau_dev` 3.9e-5), `alpha_std` 0.115, банк (25.4k L3),
  мета-лестница 0.97. Открытый вопрос: включится ли VSA, когда кэш упрётся в горизонт
  512 или данные потребуют ассоциативной памяти.
  **Горизонт кэша — токенный и runtime-настраиваемый**: 512 = `cache_horizon_tokens`
  (0 = AUTO = `tau_max`), одинаково в обеих фазах; эффективный контекст = горизонт /
  гранулярность записи (запись = окно `seq_len`=384) → ~1–2 окна и на обучении, и на
  инференсе (`ctx = tokens[-L:]`). Больше на инференсе: поднять `cache_horizon_tokens`
  (2048–4096) и/или sentence-ring (до 12 пулов предложений); переобучение не нужно
  (политика кольца — runtime), но экстраполяция на >2 окон не проверена — валидировать
  на eval.
  **Предел «миллион токенов»:** механически — да (кольцо ≈ 2600 окон ≈ 0.5GB по
  низкоранговому K/V), но: (а) чтение кэша линейно растёт (~0.5GB/токен) — генерация
  замедляется на порядки, это KV-подобный режим; (б) модель училась на ~1–2 окнах —
  внимание по тысячам ключей размажется (диффузия softmax); (в) задуманный длинный
  контекст — не кэш, а VSA/банк (образ/gist фиксированного размера, ёмкость ограничена
  кросс-током), и сейчас VSA-carry спит. Проверка: поднять `cache_horizon_tokens` на
  eval и смотреть выигрыш.
  **Почему модель выбрала кэш (ключ к дальности):** горизонт кэша по построению =
  верхняя шкала VSA (`cache_horizon_tokens=0 → AUTO = cfg.tau_max` = 512). При равном
  охвате VSA не даёт ничего сверх (суперпозиция с кросс-током vs вербатим K/V) — выбор
  рационален. Выученная τ-лестница сжалась (6.65…230 vs канонов 8…512) — модели нужно
  меньше 512. Дальше 512 не тянет НИ ОДИН механизм: VSA — по дизайну шкал, кэш — по
  AUTO-горизонту. Для дальности нужна работа над носителем: удлинение τ-лестницы
  (обучаемая шкала) или дальнобойность банка L2/L3 (дискретные записи вне timescale'ов).
  **Плюс и минус выбора кэша (наблюдение оператора):** модель идёт по градиенту
  наименьшего сопротивления — кэш даёт немедленную награду CE, VSA/мультимасштаб платят
  позже и диффузно → `w_m2v` 0.22→0.011 (градиентная голодовка), τ сжалась, гейт кэша
  насыщен. Плюсы: эффективность (тот же охват, дешевле/точнее), стабильность (гладкий
  путь), прогресс (loss 22→11.4). Минусы: неиспользованная ёмкость VSA/мультимасштаба,
  **lock-in** (нет градиента → нет улучшения → нет градиента), риск «нарядного n-gram»
  (val 8.49 > униграммы 7.48). Как заставить трудный путь платить (без форса): явная
  супервизия (bind round-trip), данные/задача с дальней зависимостью, куррикулум
  (кэш ПОСЛЕ становления VSA — сейчас наоборот), цена лёгкого пути (бюджет/штраф
  чтения кэша). Маркеры второго шага: `w_m2v` перестаёт падать, τ-диапазон расширяется,
  CARRY оживает.
  **Выравнивание горизонтов (принцип):** горизонт кэша должен ложиться на шкалы VSA
  (лестница 8/32/128/512, ×4) — 512, 2048, 8192… Текущая невыровненность: горизонт 512
  при окне 384 → 1.33 записи, кольцо держит 1 окно (384), 128 токенов горизонта
  простаивают (эффективный охват = 384, не 512). Выравнивание: окно 512 (=1 запись на
  τ4), либо окно 256 (=2 записи на 512, 8 на 2048 — идеальный тайлинг), либо горизонт,
  кратный окну (768/1152/1536). На будущее: горизонт = 512×4^k вместе с удлинением
  τ-лестницы — тогда охваты памяти и timescale'ы совпадают по построению.
  **Оптимум чисел (обоснование):** жёсткое ограничение — τ3(128) хочет ≥3× разрешения
  (seq ≥ 384; при 224 было 1.75× — плохо). VSA-чанк 32 мягкий (tail-pad по M37
  безвреден), conv 48 / cov 64 мягкие (F.pad и C=min(chunk,L) держат хвосты).
  Кандидаты при d=24/40GB: 256 (−33% памяти, кэш 512 через 2 записи, но τ3 2.0× — ломает
  дизайн); 320 (−17%, τ3 2.5× — запасной при OOM); **384 (оптимум: τ3 3.0×, 12 чанков,
  память 32–37GB, кэш отдаёт 384/512)**; 512 (τ3 4.0× + кэш ровно 1 запись = весь
  горизонт + 16 чанков — идеал, но +33% памяти = 43–49GB → OOM при d≥20; для d≤16 или
  A100 80GB, тогда `max_entries` 12→16). Batch всегда 1 (B>1 множит токены/шаг и память
  без выигрыша).
- **τ-лестница учится**: выученный диапазон 6.99…286 (41×) против канонических 8…512 (64×) —
  модель стягивает временной размах задачи; per-layer dev std 0.039.
- **Фантом спит**: `sal_p99≈1.03` ниже порога 1.1; хвост растёт (1.016@1045 → 1.036@4345).
  UCL births=0 (концептам нечего рождать), фантомный канал 32/64 бит (рост in-place ждёт концептов).
- **Intent-шина — сильный канал**: per-layer нормы ~19k, `bus_head_proj` 7.2; под наблюдением.
- **«Таймеры» вместо измерений** (цепочка M57): `mat` (pen_init=1.0 → readiness = decay от 1.0,
  симуляция даёт ровно 0.833 на 3135 = M47-«mat 0.82»), `lbg_tau = gate_tau(mat)`, UCL `_mature`
  от resvar — симуляция, не измерение. Исправлено в M58 (`pen_init=0`).

## Ответы (сессия 2)

1. **Tau-число:** Фундаментальная константа EVA. Используется везде. Найдено через анализ кода:
   - `_tau_s = [8, 32, 128, 512]` — базовые VSA-timescales
   - `_vsa_log_param` — обучаемые log-параметрыtau-лестницы
   - `_tau_l_dev` — per-layer отклонения
   - tau = exp(b_d) — per-block timescale
   - Fibonacci связан через `memory_tau_hi = F_21 = 10946`
   - **Ключевой момент:** tau не = Fibonacci. Tau — многомерная обобщённая константа. Fibonacci — частный случай для 2D.
2. **96+ слоёв:** В первую очередь bind. Gradient vanishing решается bind/unbind операциями.
3. **Symmetry:** Можно изучить самостоятельно через код.
4. **Compressor:** Потеря точности = 1% при 10x сжатии.
5. **Bridge vs attention (КЛЮЧЕВОЕ - ПОЛНЫЙ АНАЛИЗ):**
   - **Attention:** читает **готовые токены** (post-formalization). Накапливает попарную схожесть (квадратичная сложность). KV-матрица растёт с контекстом.
   - **Bridge:** читает **скрытое состояние** (pre-formalization). Понимает связь **до формализации токена**. Постоянный размер (n_layers × bridge_dim). Работает через EMA-поток.
   - **Bridge injection:** происходит **до** блока (bind/mirror/MLP). Hidden state ещё "сырой" — токен не выбран.
   - **BridgeGLU:** читает delta (разницу между текущим состоянием и памятью), produces live semantic gate для MLP **до** MLP.
   - **Self-supervision:** каждый слой independently предсказывает embedding следующего токена (cosine loss на каждом уровне).
   - **Temporal flow:** persistent bridge_stream переносится между forward-вызовами (память о семантической структуре).
6. **VSA scaling:** Да, с учётом bind в WB.

## Полное описание архитектуры EVA

### Обзор

EVA (Единая Вычислительная Архитектура) — многосистемная архитектура, комбинирующая когнитивные науки с deep learning. Каждый компонент решает конкретную задачу и связан с другими через tau-иерархию.

**Текущие параметры:** 146.67M (D=2560, n_layers=24, G=32, vocab=65536)

### Компоненты архитектуры

#### 1. GroupedCognitiveMirror (32 эксперта на слой)
**Файл:** `core/mirror.py`

**Что делает:** Каждый слой содержит 32 эксперта-зеркала. Каждый эксперт работает в своём d=80 подпространстве (D=2560/G=80). Эксперты маршрутизируют вход через precision gate, вычисляют 4 сигнала коррекции (temp, pred, smooth, sym) и дают полный градиент pred_error.

**Зачем:**
- Разбиение на экспертов = sparse computation (как MoE, но с когнитивной маршрутизацией)
- Per-expert K-space (k=32) позволяет каждому эксперту работать в своём контексте
- Meta-gate учится доверять/игнорировать каждого эксперта

**Зависимости:**
- **Maturation** — запись в private_mem открывается при mat_gate[i] >= 0.3
- **BridgeGLU** — MLP gate modulated by bridge semantic delta
- **PrecisionGate** — маршрутизация по pred_error
- **Bridge** — semantic delta для BridgeGLU

**Ключевые параметры:**
- `G=32` — количество экспертов
- `k=32` — размерность K-space
- `private_mem=True` — cross-expert private memory bank
- `expert_asymmetry=True` — разные alpha, log_scale, W_proj для каждого эксперта

---

#### 2. SemanticBridge (Кросс-слойный семантический мост)
**Файл:** `core/bridge.py`

**Что делает:** Shared probe head emits semantic vector s_l = probe(h_l) на каждом слое. Векторы формируют кросс-слойный поток:
- **DEPTH:** bottom-up (свежие от нижних слоёв) + top-down (carried от верхних)
- **TIME:** persistent bridge_stream (EMA) переносится через forward calls
- **SELF-SUPERVISED:** probe обучается предсказывать next-token embedding (cosine loss)

**Зачем:**
- Связывает слои семантически (не просто skip connections)
- Даёт плотный градиент на каждом уровне глубины
- Позволяет нижним слоям "видеть" контекст верхних

**Зависимости:**
- **Maturation** — bridge injection gated by mat_gate[i]
- **LayerBridgeGate** — УДАЛЁН в M64.5 (мёртвый канал: гейт считался и выбрасывался,
  `lbg_diversity`=2.75e-6 без градиента, B3-инцидент: 0.26 train vs 3.69 eval;
  идея «health-gated bridge routing» — кандидат M65 с A/B)
- **BridgeGLU** — bridge delta модулирует MLP gate
- **IntentBridge** — parallel semantic stream

**Ключевые параметры:**
- `bridge_conn=0.1` — aux loss weight
- `bridge_dim=256` — semantic vector width
- `bridge_depth=True` — cross-layer injection

---

#### 3. MaturationController (Единый контроллер созревания)
**Файл:** `core/maturation.py`

**Что делает:** Per-layer maturity M_l(t) in [0,1], гейтирующий ВСЕ wake-up сигналы:
- Bridge injection
- Private memory write
- Intent bus
- LayerBridgeGate

**Формула:** `M_l(t) = sigmoid((t - (T0 + alpha*tau_norm_l*T_delay)) / delta_t)`

**Зачем:**
- Deep-first созревание: глубокие слои (большой tau) открываются первыми
- Предотвращает catastrophic interference
- Bridge readiness: компетентность bridge определяет готовность

**Зависимости:**
- **Bridge** — readiness от cosine loss bridge probe
- **VSA tau ladder** — tau_norm для определения порядка открытия
- **Все компоненты** — maturation гейтирует их активность

**Ключевые параметры:**
- `matur_T0=8000` — начало ramp
- `matur_T_delay=8000` — задержка deepest layers
- `matur_delta=4000` — ширина ramp
- `matur_r0=0.3` — readiness sigmoid center

#### 4. StreamingMemoryBank (Иерархическая память L1→L2→L3)
**Файл:** `core/memory_bank.py`

**Что делает:** Три уровня памяти:
- **L1 (immediate):** rolling buffer of last K sentence embeddings (без обучения)
- **L2 (short-term):** learned bank with N slots, novelty-based write gating
- **L3 (emergent concepts):** clusters L2 keys by cosine similarity, concept birth/update

**Зачем:**
- L1: имmediate контекст (последние предложения)
- L2: краткосрочная память (выученные ассоциации)
- L3: долгосрочная паметь (эмерджентные концепты)

**Зависимости:**
- **Maturation** — записи gated by mat_gate[i] >= 0.3
- **Per-layer** — memory bank вызывается внутри цикла слоёв

**Ключевые параметры:**
- `mem_l1_slots=3` — L1 buffer size
- `mem_l2_slots=16` — L2 bank size
- `mem_l3_concepts=8` — L3 concept slots
- `mem_min_write_mat=0.3` — min maturation для записей

#### 5. ThinkingTokenHead (Адаптивное мышление)
**Файл:** `core/reasoning.py`

**Что делает:** Chain-of-thought reasoning с adaptive depth. Thinking tokens генерируются динамически, gate определяет когда остановиться.

**Зачем:**
- Модель может "думать" дольше на сложных задачах
- Adaptive depth: не все токены требуют одинаковой глубины
- Self-supervised: reasoning gate обучается предсказывать.stop

**Зависимости:**
- **Maturation** — reasoning gate может быть gated maturation
- **Bridge** — reasoning context влияет на bridge

**Ключевые параметры:**
- `reasoning_max_steps=8` — max reasoning depth
- `reasoning_gate_stop_threshold=0.5` — stop threshold

#### 6. HybridHead (Гибридная голова)
**Файл:** `core/embedding.py`

**Что делает:** `output = sigmoid(x) * (1 + softmax(x))` — выпуклая комбинация sigmoid и softmax.

**Зачем:**
- Sigmoid сохраняет лакуну (потенциал несовпавшего)
- Softmax добавляет нормализованную конкуренцию
- "Демократия с лидером": softmax = лидер, sigmoid = народ

**Зависимости:**
- **Bind** — выход head связан с embedding через tie_weights

---

#### 7. IntentBridge (Мост намерения)
**Файл:** `core/stack.py` (внутри forward)

**Что делает:** Per-head intent stream (G×K_max), flows through depth (per-layer) and time (EMA). Experts "подхватывают" восходящий сигнал.

**Зачем:**
- Связывает "намерение" модели с её конкретными действиями
- Глубокие слои видят intent от мелких
- Cross-layer bus: network-wide gist

**Зависимости:**
- **Maturation** — intent bus gated by mat_gate[i]
- **Bridge** — parallel semantic stream

---

#### 8. LayerBridgeGate + SpectrumGate
**Файл:** `core/layer_bridge_gate.py`

**Что делает:** Per-layer intelligent gate для bridge routing. SpectrumGate = `sigmoid(logits) * (1 + softmax(logits/tau))`.

**Зачем:**
- Независимая активация по признакам (sigmoid)
- Относительный акцент среди признаков (softmax)
- tau связывает с maturation (self-regulation)

**Зависимости:**
- **Maturation** — tau из maturation gate
- **Bridge** — gate управляет bridge injection
- **Diagnostics** — per-layer health metrics

### Поток данных (forward pass)

```
tokens → PartitionedEmbedding → [RoPE] → h
    ↓
Memory Bank (per-layer, maturation-gated)
    ↓
Intent Bridge (per-layer, maturation-gated)
    ↓
[Layer 0] SemanticBridge.inject_layer(0, h)
    ↓
GroupedCognitiveMirror (32 experts, PrecisionGate)
    ↓
BridgeGLU (semantic delta → MLP gate)
    ↓
MLP (SwiGLU, maturation-gated)
    ↓
LayerBridgeGate → SpectrumGate
    ↓
[Layer 1..23] (repeat)
    ↓
SigmoidCodedHead → logits
    ↓
compute_loss (CE + aux losses)
```

### Tau-иерархия (связи между компонентами)

```
VSA tau ladder (τ_min=8..τ_max=515)
    ↓
Maturation tau_norm (normalize tau to [0,1])
    ↓
Maturation gate M_l(t) per layer
    ↓
┌─────────────────────────────────────────┐
│ Bridge injection (gated by M_l)        │
│ Private memory write (gated by M_l)    │
│ Intent bus (gated by M_l)              │
│ LayerBridgeGate (tau = M_l)            │
│ BridgeGLU (modulated by bridge delta)  │
│ Memory Bank (gated by M_l per-layer)   │
└─────────────────────────────────────────┘
```

### Aux losses (вспомогательные функции потерь)

| Loss | Weight | Purpose |
|------|--------|---------|
| CE | 1.0 | Main language modeling |
| bridge_conn | 0.1 | Bridge next-token prediction |
| diversity | 0.001 | Decorrelate expert outputs |
| balance | 0.026 | Load balancing across experts |
| gate_repulse | 0.3 | Push gate variance up |
| alpha_novelty | 0.05 | Push per-expert alpha apart |
| reinforce | 0.001 | Align gate with usefulness |
| gradalign | 0.0 | Align MLP gate with CE gradient |
