## 0. Резюме для агентов (TL;DR)

- Модель EVA-CLM (183.14M параметров, 24 слоя, D=2560, словарь 65536) обучена
  ~13.6k шагов; best val (CE, нат/токен) = **7.9260** (на hold-out).
- **Генерация в smart-режиме на этом чекпоинте даёт словесный салат**
  (служебные слова + пунктуация, без структуры) — полный транскрипт в §3.
- **Диагностика:** маркер `BIAS-DECOMP` (доля позиций, где argmax полных логитов
  совпадает с argmax одного лишь `token_bias`) прошёл путь **0% → 100%** между
  шагами 3080 и 10560. То есть контекст перестал влиять на top-1 выбор модели:
  предсказания стали определяться униграм-биасом.
- **Гипотеза:** модель сидит на потолке своего бит-независимого семейства головы
  (независимый замер: bigram-потолок семейства **7.96** нат, при этом полная
  биграммная модель даёт 3.73, униграмма 4.72). На этом потолке при слабом
  контексте **оптимально хеджировать** (уплощаться и опираться на приор) —
  CE улучшается, argmax-структура деградирует. Механизм уплощения:
  `log_temp` (побитная температура кодового чтения) вырос 0.106 → 0.281 → 0.310.
- **Решающий тест уже запущен:** в текущий прогон включён парный канал головы
  (rank-16 Ising-поправка; по замеру закрывает 66.7% разрыва бит-независимости).
  Предсказание: если контекст снова начнёт выигрывать argmax — маркер пойдёт к 0%,
  val ниже 7.9; если нет — бутылочное горлышко глубже семейства головы.

## 1. Модель и конфигурация

### 1.1 Архитектура (кратко)
Ствол: 24 слоя, каждый — conv-ветвь + VSA-память (4 τ-шкалы: 8/32/128/512, обучаемая
лестница) + bind (trajectory_spiral, K=32) + спектральная ветвь + grouped MLP
(32 группы, expand 4) + «зеркало» (GroupedCognitiveMirror: эксперты, приватная
память, K-space предсказание). Когнитивные надстройки: logit_cache (многошкальный
кэш 8..8192), memory_bank, unified_concept_layer (UCL), intent bridge (stencil),
explicit_reasoning (adaptive), meta_trust, bridge (SemanticBridge, 1.38M параметров).

Голова (`SigmoidCodedHead`, `head_mode=sigmoid_coded`, `normalize=True`):
`logits_v = u·c_v + token_bias + (фантом-канал) + (pair-канал)`, где `u` — 64-битное
кодовое состояние (sigmoid от `z/T + bit_bias + bus_bias`), `c_v ∈ {0,1}^64` — коды
словаря (ровно 6 активных битов на токен, twin_free-упаковка). Семейство
**бит-независимо** (без взаимодействий битов) — это ключевое ограничение (§4.4).

### 1.2 Параметры
- Всего: **183,139,929** (без pair) / **183,141,977** (с pair rank-16; +2048).
- Чекпоинт `best 13640.pt`: step=13640, best_val_loss=7.926045485217162 (вариант
  «ночной»); Drive-версия того же шага пере-сохранена на резюме с val=7.9129
  (веса идентичны, отличается конверт: RNG/stream-позиции/best_val_loss).
  Размер 2,884,335,550 B (2.69 GiB); локальный MD5 33228d483d06a3050e01e9764fe76fcf;
  MD5 Drive-варианта 9ddb5861d405322047c3b1aba45771fa.
- В чекпоинте: `model` (2787 ключей), `optimizer`, `param_names`, `ledger`,
  `birth_ledger`, `pvel` (P3-инструменты). Pair-ключей нет (сохранялся до включения
  флага).

### 1.3 Режим обучения
batch=1, seq_len=384 (384 токена/шаг), ~58–60 ток/с (~6.5 с/шаг), lr базовая 6e-4
(τ-LLRD: группы 0.00012…0.001104), betas (0.9, 0.95), wd 0.01, warmup 300,
AGC c=0.1 (τ-зависимый), aux-балансер spectral-align (align_every=8), aux kill
switch — measure-only. Активные флаги текущего прогона: `contradiction_field=True`
(P4-3 детектор, монитор), `head_pair_rank=16` (P1-2 парный канал), всё остальное —
дефолт (в частности `tie_grad=False` — см. §5.6).

## 4. Диагностика, объясняющая генерацию

### 4.1 BIAS-DECOMP (маркер отчёта analyze.py, HEAD-секция)
Что измеряется: на 48 позициях реального текста сравнивается `argmax` полных
логитов с `argmax` одного `token_bias`; отдельно классифицируется argmax
контекстной части (`logits − bias`) и полных логитов (word/punct).

| | 3080 | 10560 | 13640 |
|---|---|---|---|
| `argmax==bias` | **0/48 (0.0%)** | **48/48 (100%)** | 48/48 (100%) |
| ctx-argmax word/punct | 46 / 0 | 48 / 0 | 48 / 0 |
| full-argmax word/punct | 0 / 0 | 0 / 48 | 0 / 48 |
| `log_temp` mean | +0.1058 | +0.2807 | +0.3098 |
| best_val | 9.8316 | 7.9828 | 7.9260 |

Чтение: на 3080 контекст **выигрывал argmax на всех позициях** (модель
различала токены по состоянию). К 10560 контекст не выигрывает ни на одной:
top-1 всегда равен bias-токену (это пунктуация). Контекстная часть при этом
несёт word-сигнал (ctx-argmax=word 48/48) — но её вклад недостаточен, чтобы
перебить bias в сумме.

### 4.2 log_temp: что это (код)
`log_temp` — **побитная** температура кодового чтения (не словарная):
```python
# core/embedding.py, SigmoidCodedHead._gates
h_g = h.reshape(B, L, self.K, -1)
z   = (h_g * self.readout.unsqueeze(0).unsqueeze(0)).sum(dim=-1)   # (B,L,64)
T   = torch.exp(self.log_temp)                                     # (64,)
T   = T + (T.clamp(0.1, 10.0) - T).detach()   # ST-кламп: forward [0.1,10], backward identity
z_data = z / T                                 # «мягкость» битов
zt = z_data + self.bit_bias  (+ bus_bias)
```
Рост `log_temp` 0.106 → 0.310 ⇒ T 1.11 → 1.36 ⇒ сигмоид-биты мягче ⇒ `u·c_v`
(сумма 6 активных битов) выравнивается по словарю ⇒ контекстный вклад теряет
различительную силу ⇒ argmax падает на bias. Старое значение ref: +0.0188 на
шаге 1398.

### 4.4 Независимый замер потолка головы (P1-1, bigram-прокси, тот же корпус)
| Модель | CE, нат |
|---|---|
| oracle unigram | 4.72 |
| oracle bigram (полный softmax) | 3.73 |
| **семейство головы (PoB, бит-независимое)** | **7.96** |
| uniform (u=0) | 11.09 (ln 65536) |
| семейство + pair rank-16 | **5.14** (закрывает 66.7% разрыва) |

Цена битовой независимости **+4.2 нат**; rank-16 закрывает 66.7% разрыва.
**ВАЖНАЯ ПОПРАВКА (замер на реальном hold-out, файл eval):** абсолютные числа
пробы (4.72/3.73/7.96) получены на другом стриме и НЕ сравнимы с val. Прямой
замер базовых линий на том же файле, что использует eval
(wb/token_stream_WAR_eos.bin, 23.9M токенов; обучение на первых 75%, CE на
последних 25%):

| Базовая линия | CE, нат |
|---|---|
| uniform | 11.0904 |
| unigram (эмпирический) | 7.7440 |
| bigram (эмпирический) | 7.5426 |
| **модель (val 13640)** | **7.9260** |

То есть модель **хуже униграммы на 0.18 и хуже биграммы на 0.38** на своём же
hold-out: она выучила частичную маргиналу и почти никакого контекста. Оговорка:
модель обучена на миксе стримов, а hold-out — WAR; часть разрыва может быть
доменным (униграмма-«соперник» фитится на самом WAR). Но порядок ясен: это
режим «около униграммы», и генерация-салат этим полностью объясняется.
Проба потолка семейства должна быть пере-замерена на стриме eval — иначе
абсолютные числа несопоставимы.

### 4.6 emphasis_gain: «сигмоид против софтмакса» — прямой замер

Голова использует гибридный гейт (`core/adaptive_gate.py::hybrid_gate`, log-режим):
```python
relative = softmax(z_data / T, dim=-1)                 # конкуренция 64 битов (prior-free данные)
u = zt + gain * (log1p(relative) - log1p(1/K))         # K=64; gain — обучаемый (init +1.0)
base = logsigmoid(-u).sum(dim=-1)
```
При `gain > 0` выделяющиеся биты усиливаются (код резче), при `gain < 0` — подавляются
(код площе). Обученный `emphasis_gain`:

| | 3080 | 10560 | 13640 |
|---|---|---|---|
| **`emphasis_gain`** | **+0.7743** | **−0.1643** | **−0.5229** |
| `log_temp` mean | +0.1058 | +0.2807 | +0.3098 |
| BIAS-DECOMP | 0% | 100% | 100% |

Модель прошла через ноль и **вывернула софтмакс-эмфазу наизнанку**, причём инверсия
ускоряется: −0.16 за 7480 шагов, затем −0.36 за 3080. Вместе с ростом `log_temp`
(мягчение битов) оба обучаемых рычага ведут к одному: код-пространство теряет
контраст ⇒ `u·c_v` выравнивается по словарю ⇒ argmax падает на униграм-биас.
Это тот же «хеджирующий» ответ модели: при неинформативном контексте уплощение
даёт лучший CE, чем резкий-но-неправый код.

### 4.7 Гипотеза причинной цепочки (проверяемая)
1. P0-1 (F2) фикс: кламп τ_s (fp32-предохранитель скана) **связывает** на мелких
   слоях: τ_s 0.33→1.0, decay 0.048→0.37 ⇒ VSA-память мелких слоёв стала жить
   ~×8 дольше ⇒ рост норм (h_norm 160 → 500–3600).
2. Рост норм ⇒ периодические сатурации u (u_max ~330–360) ⇒ CE-градиент через
   софтмакс в насыщении ≈ 0.
3. Модель учится уплощаться (`log_temp` ↑) — чтобы сохранить градиент/калибровку.
4. Мягчение битов ⇒ контекст слабеет ⇒ хеджирование на униграм-приор ещё
   выгоднее (петля).
5. Наблюдаемые симптомы: BIAS-DECOMP 100%, H≈6–7 нат, генерация-салат, val
   улучшается (калибровка), argmax-структура деградирует.

Альтернативные объяснения (для агентов): (a) log_temp рос независимо от
сатураций (просто выученная калибровка); (b) переход 0%→100% связан с другими
событиями того же окна (открытие logit_cache на 3520, разморозка глубины до 24,
рампа зрелости, батч аудит-фиксов); (c) хеджирование — вообще правильный ответ
(контекст реально неинформативен на этом объёме данных), и генерация появится
только при val ниже униграммы (4.72).

### 5.5 Варианты вмешательства (меню для агентов)

4. **Расширение семейства** сильнее rank-16 (полная Ising/больший rank, морфокоды

5. **Ослабление τ-клампа** (`vsa_decay_floor_k` 2.0 → 1.5: безопасный пол 0.75,

6. **Только обучение** — если контекст реально неинформативен на 13k шагов,
   генерация появится при val < 4.72 (уровень униграммы).

## 8. Словарь (для агентов)
- **val** — CE на hold-out (нат/токен), main-метрика.
- **BIAS-DECOMP** — доля позиций, где argmax полных логитов = argmax одного
  `token_bias` (униграм-приора).
- **log_temp** — побитная (64 бита) температура кодового чтения; T=exp(log_temp),
  ST-кламп [0.1,10].
- **emphasis_gain** — обучаемый множитель центрированной софтмакс-эмфазы в
  `hybrid_gate`; init +1.0; отрицательное значение = биты-«победители» подавляются
  (уплощение кода).
- **τ_s-кламп (P0-1/F2)** — предохранитель fp32-скана VSA: τ_s ≥ 0.5·k; на мелких
  слоях связывает (τ_s 0.33→1.0).
- **PoB** — семейство головы: `q(v|u) ∝ exp(Σ_k c_vk u_k)` (бит-независимое).
- **Сатурация** — |u| > ~12 (sat=1.0 при u_max ~330–360); CE-градиент ≈ 0.
- **Зеркало (mirror)** — модуль per-layer предсказания в K-пространстве с
  экспертами и приватной памятью.
- **Леджер** — парные измерения ΔCE при выключении регулятора (P3-1).


### 4.8 Аудит реализации головы: что могли не предусмотреть

Список кандидатов (с замерами/ссылками; для внешних агентов — как чек-лист):

1. **Поправка базовых линий** (§4.4): модель около униграммы, а не «на потолке
   семейства». Первое, что было не предусмотрено — сопоставимость пробы и val.
2. **emphasis_gain не ограничен** и вывернут моделью в отрицательную область
   (+0.77 → −0.16 → −0.52): механизм самоподавления софтмакс-эмфазы. Нет
   телеметрии/порога, сигналящего об инверсии (нашли только через analyze).
3. **Приор не выучен**: 	oken_bias инициализирован нулями, после 13.6k шагов
   std=0.81 — при маргинале 65k-словаря ожидается ~3–4 ната разброса.
   it_bias std=0.059 (факторизованный приор ещё площе). Итог: общий приор
   почти плоский, CE ~на униграмме. Почему softmax-CE не дотягивает приор —
   открытый вопрос (wd 0.01? конкуренция с контекстным членом? масштаб LR?).
4. **log_temp (побитная температура) без верхней границы** (ST-кламп [0.1,10]):
   вырос 0.106 → 0.310, мягчит биты (T 1.11 → 1.36).
5. **Связанный readout** (
eadout = embed.basis, tie_readout=True): геометрия
   чтения головы делится с входным эмбеддингом и движется медленно (std 0.168
   против орт-инита 0.158 — +6% за 13.6k шагов; ранее замерялось −1.9% за 7315).
   Если входная цель доминирует, чтение контекста структурно ограничено.
6. **Гейт лакуны схлопнут**: lacuna_w=29.84, lacuna_b=-3.67 → при ell_rel≈1
   g=σ(−3.67)≈0.025 — «канал неизвестного» фактически выключен; салиентность
   плоская (H/Hmax=1.0). Механизм может тихо умереть, никто не сигналит.
7. **Стена head_u_wall** (u0=6.0, w=1e-3): при типичных |u| 6–10 она активна
   постоянно и давит |u| вниз — постоянное давление в сторону уплощения битов.
8. **Стенсил шины на рейле**: сырой выход us_head_proj растёт (5.0 → 861 →
   1682 norm/pos), но кап head_bus_cap=3.0 (amax, scale-invariant) держит
   применённую величину постоянной ⇒ влияние стенсила зафиксировано по модулю
   (меняется только направление). Если модели нужно больше — она не может.
9. **Плоская салиентность → петля**: салиентность = f(логиты); плоское
   распределение ⇒ плоская салиентность ⇒ вырожденный intent-сигнал ⇒ стенсил ⇒
   биты. Возможен самоподдерживающийся контур вырождения.
10. **srl_apply=False**: контур разрешения (SRL) не применяется — на инференсе
    нет механизма обострения кода (известное выключение, но в текущем режиме
    оно означает отсутствие «дожатия»).
11. **Фантом-канал**: леджер даёт −0.085 (стоит дороже, чем даёт); phantom_basis
    std 0.018 (слаб).

Проверки, которые это разделяют: (а) проба потолка семейства **на стриме eval**
(unigram/bigram/PoB — §4.4); (б) проба «u → следующий токен» (несёт ли состояние
информацию сверх приора); (в) динамика 	oken_bias (почему приор не сходится);
(г) контроль emphasis_gain/log_temp как маркеров режима.
