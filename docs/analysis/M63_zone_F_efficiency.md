## 0. Главное

1. **«723M параметров» — неверно для этого чекпойнта.** В `checkponts/best.pt` (step 7315) ровно **370 752 690 тензоров** = **212.07M параметров + 158.68M буферов** (V_dct: 24×6.5536M = 157.3M). 2. **Главный расход — не forward, а три полных backward на шаг.** `LossBalancer.backward` делает `torch.autograd.grad` трижды: CE (`training_control.py:358`), `aux_total` (`:397-400`), bypass/gradalign (`:437-441`). При gradient checkpointing это ~3 обхода графа с рекомпьютом — структурный множитель ~2.5–3x.
3. **TF32 уже включён** (`cell 3:20-21`), поэтому «пик fp32 19.5 TFLOPS» — не тот знаменатель: фактический пик матмулов ≈ **156 TFLOPS TF32**, bf16 ≈ 312. Эффективность шага ~0.2–0.5% — режим launch/latency-bound.
4. **Курсор данных: смен стрима НЕ было.** `offset = 3 277 568 = 448 × 7316` — ровно все токены, прочитанные с шага 0. `stream_idx=6` — индекс выбранного стрима, не счётчик смен. Оценка «~6 смен / чанк 0.5M» ошибочна; естественная смена — раз в ~10^5 шагов (файлы по ~30–50M токенов).
5. **M62: 250 шагов = 112k токенов**, не 6.9M: формула печати `cell 4:134` завышает в 61x (исправлено 560e569).
6. **Эпоха**: 1.3B/448 = 2.90M шагов; пройдено 7315 = **0.25%**. Бюджет 167 юнитов × 5.3/ч ≈ 31.5ч; израсходовано ~16.3ч (7315×8с); остаток ~15ч ≈ +3.1M токенов. Итог ~6.4M токенов = 0.22% эпохи = 0.15% от Chinchilla-оптимума (20 ток/параметр для 212M ≈ 4.2B) — режим compute-limited.
7. **Рычаги**: (1) 3 backward → 1: **1.5–1.9x**; (2) bf16 AMP: 1.1–1.4x + 0.65–0.85x памяти, открывает batch 4; (3) batch/seq ↑: 1.3–1.7x; (4) срезать early-eval: 1.02–1.05x; (5) compile: 1.0–1.2x при высоком риске.
8. **Данные не узкое место**: корпус исчерпать нельзя (0.25% за 16ч); ротация 250 шагов = 30 секунд обучения на жанр; для CE-стабильности разумно удлинить до ~1000–2000 шагов, 250 — ограниченный A/B.

### 2.4 AMP (bf16)

**(а) Память и скорость.** bf16: 8 бит экспоненты (диапазон fp32), 8 бит мантиссы. Активации ×0.5; мастер-веса и Adam fp32 (params 848MB, grads ~580MB при depth 12, Adam ~1.3GB, буферы 635MB ≈ 3.4GB статики). Но spectral, mirror, VSA-сканы, VPM — **явные fp32-якоря** и составят большинство по FLOPs. Ожидаемое снижение пика: **0.65–0.85x**, не 0.5x. По скорости: TF32 уже 156 TFLOPS, bf16 312 (2x на матмулах), eligible-доля ≈40–45% → реально **1.1–1.4x** (низкая уверенность, нужен замер).

**(б) Риски точности.** Градиенты 1e-10: экспонента bf16 держит, относительная квантованность ~0.4%; автоград складывает в fp32. Лог-отношения ветвей, `|u|−6` в bf16 (абс. ошибка ~0.02), softmax по 65536 логитам — fp32-список autocast, `u @ codes.T` в bf16 TC с fp32-аккумуляцией → отн. ошибка логитов ~0.4% → CE ~1e-3 нат. Реальный краш-риск — dtype-mismatch (класс B10b, `concept_layer.py:235-236`, закрыт), но других `index_*`/in-place путей много (bank keys/vals — буферы, `_cached_*` — fp32).

**(в) GradScaler.** Для bf16 не нужен; в ноутбуке `scaler=None`. В `train.py` он строится и применяется вручную — при `use_amp=True` это fp16-семантика; autocast там обёрнут только embedding, так что модель фактически fp32, а scaling — накладные.

**(г) Итог.** Время: **1.1–1.4x** (низкая уверенность); память: **0.65–0.85x**. Главная ценность — освобождение VRAM под batch 4 / seq 448. «~2x» из cell 4:86 — оптимистично.

## 4. Риски

1. **Балансер — дизайн, а не баг.** Сведение трёх backward меняет композицию градиента; нужен A/B 1000–2000 шагов с `ggeo`/val.
2. **bf16 + fp32-якоря**: смешанные dtype-пути — класс B10b; перед включением 50 шагов с проверкой RuntimeError.
3. **Train.py ≠ ноутбук**: AMP-путь в `scripts/train.py:523-594` половинчатый; правки делать в ячейке.
4. **Курсор после M62**: best.pt несёт `stream_chunk_steps=0` (снят до M62); падение откатит данные на ~0.5M токенов.
5. **Ошибка печати токенов/чанка** (исправлена).
6. **Память при batch 4**: live 31.4GB при depth 12/24 и recompute ON; без AMP batch 4 почти наверняка OOM.
