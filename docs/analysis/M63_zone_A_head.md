## 0. Главное

1. **64 направления readout — не информационный бутылочник, а оптимизационный.** 64 вещественных числа несут заведомо больше 16 бит, нужных для словаря 65536; измеренный ∂CE/∂h лежит **ровно** в span(readout) (ортогональный остаток 0.0), но код-путь сейчас **вредит**: на окне 224 токена CE(code-only)=12.84 > CE(bias-only)=8.65, uniform=11.09. Проблема не в полосе, а в том, что ствол не пишет ответ в зонды и что readout почти не учится.
2. **Многопроходная голова с тем же readout информационно пуста:** `z2 = R(h + Q(z1)) = z1 + R·Q(z1) = F(z1)`, т.е. z2 — детерминированная функция z1, `I(Y;z2) ≤ I(Y;z1)`. Выигрыш может дать только вторая (независимая) матрица чтения или попарные члены.
3. **RMS-нормализация u — не тот фикс.** Измеренный u ∈ [−4.8, −0.9], sat=0, head_wall=0. При `final_norm_w ≡ 1` (проверено по чекпойнту), `‖h‖ = √D = 50.64`, `|z| ≤ ‖h‖` и `T ≥ 0.1` (ST-клэмп, embedding.py:362) числа «sat=1.0 / wall=3541» **математически недостижимы**; сначала live-захват спайка, потом фиксы.
4. **Акцент мёртв:** |emph| ≤ 0.05 против u std ≈ 0.8 (≤1.5%). Знак λ = −1.25 — шум канала, а не «анти-акцент». Правильный фикс — per-bit strength, не softplus-разложение.
5. Вердикты: **1** — переформулировать (сначала head-only тест/разморозка readout); **2** — не делать в предложенном виде; **3** — не делать как фикс спайков; **4** — per-bit `g_k` (или удалить канал).

## 2. Математика предложений

### 2.1 Задача 1 — полоса запроса readout

**(а) Сколько информации несёт 64-мерный код.** Формально `z = A h`, `A: R^2560 → R^64`, `rank(A) = K = 64` (каждый блок — rank-1), `dim ker A = 2496`. Голова — детерминированная функция z (фантомы: гейт 1e-4..4e-2, вклад в u ≤ ~0.1). Значит:
```
H(Y | h) ≥ H(Y | z)  и  I(Y; Z) ≤ I(Y; h).
```
Ранг **не** является ограничением пропускной способности: чтобы обогнать униграмму (7.84) и дойти до биграммы (4.21), нужно ≈3.3 нат ≈ 4.7 бит на позицию; 64 непрерывных координаты (даже 6-8 эффективных бит каждая) несут сотни бит. Ограничения другие:
1. **Ориентация** span(A) относительно предиктивного подпространства ствола. Измерено: `ell=0.967` ⇒ readout объясняет `1−ell² = 6.5%` ‖h‖² (для изотропного h и случайных блочных строк ожидалось `1−K/D = 2.5%`; фактические z чуть крупнее).
2. **Ранг CE-градиента к стволу = 64** (измерено точно): ствол получает обратную связь только вдоль R. Всё, что ствол запишет вне span(A), CE-кредита не получает.
3. **Readout почти заморожен**: LR = λ⁻²·6e-4 = 1.77e-4 + AdamP + cautious; std 0.1552 против init 0.1581 (−1.9% за 7315 шагов). Голова не может быстро «перенацелить» зонды.

**(б) Почему доминирует token_bias.** Градиент softmax-CE по смещению: `∂CE/∂b_v = p_v − 1[v=y]`. Для каждого токена это сигнал «попал/не попал» с SNR≈1 на вхождениях; Adam шагает ≈ lr на координату. Бюджет движения: 7315·6e-4 = 4.39 нат; измерено std 0.62 (14% бюджета), corr 0.84, наклон 0.32 — **униграмма ещё в транзиенте** (нужно std 1.67). Код-путь вынужден решать ту же униграмму через пересечение кодов: `g_u = P(k∈code) − c_yk` (std 0.30) — это маргинальный сигнал, размазанный по 64 битам. При этом `bit_bias` сдвинулся лишь равномерно (+0.25), а его разброс по битам 0.024 — прайор кода **на fixed point инициализации**. Итог: смещения (b_v, b_bit) — state-independent и решают задачу частот «в лоб»; z-путь даёт лишь условный остаток, чей систематический сигнал — корреляция `Σ_n g_u[n,k] h[n,k,i]`, а она при случайном readout близка к нулю (поэтому апдейты readout взаимно сокращаются: std не растёт). Прямое измерение: **CE(code-only)=12.84 хуже uniform=11.09** — сейчас код-канал не «недоучен», а вреден на этом окне.

**(в) Эффект расширения 64→128→256.** В этой архитектуре строки readout *и есть* биты кода (`K = code_dim`, tied), поэтому «добавить направления» = сменить кодбук (K=128 ⇒ d=20; `twin_free` требует K≥64 при V=65536 и overlap ≤ S−2), а это **не резюмируется** с текущего чекпойнта (`code_fp='65536x64-…'`). Оценка при изотропной модели (предиктивная структура ~3.27 нат равномерно по D): захваченная доля ≈ K/D, ожидаемый выигрыш:
```
K=64 : 0.082 нат;  K=128 : 0.16 нат;  K=256 : 0.33 нат
```
Это **мало** на фоне текущего дефицита 1.7 нат. При альтернативной модели («ствол сам пишет ответ в зонды») выигрыш ≈ 0. Эксперимент, различающий модели: head-only обучение (ствол заморожен) и линейный оракул — см. §6.

### 2.2 Задача 2 — многопроходная голова

Пусть `z1 = R h`, `m = top-k(z1)`, `h2 = h + Q(m ⊙ z1)`, `z2 = R h2`. Тогда
```
z2 = R h + R Q(m(z1) ⊙ z1) = z1 + R Q(m(z1) ⊙ z1) =: F(z1).
```
**z2 — детерминированная функция z1**, значит `I(Y; z2) ≤ I(Y; z1)`, и двухпроходная голова не может поднять информационный потолок; её выигрыш — только перепараметризация (оптимизационный/регуляризационный эффект). Чтобы добавить информацию, нужен **другой** readout (`z2 = R2 h`) или доступ к лакуне — т.е. это задача 1, а не «re-query». Заодно: мягкий вариант «re-query» уже реализован — это акцент `r = softmax(z/T)` (adaptive_gate.py:66), и он измеренно мёртв (|emph| ≤ 0.05).

**(а) Градиент через top-k.** ST: forward — маска, backward — тождество; оценка смещена (зависимость маски от z), дисперсия низкая; смещение O(1) у границы k-го бита и исчезает только при стабильном выборе. Gumbel-softmax: несмещён лишь при τ→0 (var ~ 1/τ²), при τ≈1 — мягкий, смещённый, но с контролируемой дисперсией. Soft-взвешивание: минимальная дисперсия, но это уже не top-k, а глобальное смешивание (и дублирует акцент).

**(б) Граф.** Пути: `z1→m→h2→z2`, `z1→h2`, `h→Q`. Опасные detach: (i) detach m — селекция не учится (и информация не появляется); (ii) detach h2 от h — CE-градиент к стволу идёт только через первый проход, но R в графе дважды → эффективный LR readout меняется (удвоение). Без detach — граф ×2 по голове (память).

**(в) Цена.** На шаг N=448: `u@Cᵀ` = 448·64·65536 = **1.88G MAC**, logsumexp 29.4M, z 1.15M; Q: 73M. Второй проход: +1.88G MAC (~0.3% от ствола ~1.4T MAC/шаг) и **+117MB** fp32-логитов (крупнейшая активация головы) на backward. Дёшево по FLOPs, заметно по памяти.

**(г) Сравнение с SRL-катастрофой.** SRL: `u ← u + α(logit ĉ − u)`, α=0.7, 2–3 итерации, шортлист по текущему u (embedding.py:442-445); цель ĉ ∈ [0,1]^K **ограничена**, α<1 — сжимающее отображение, и всё же применённый вариант дал ce 11→91 (config.py:94-96). Причина — self-confirmation: fixed points = коды, а бассейн притяжения выбирается по собственному текущему u. Многопроходная голова с **обучаемым** Q ограниченной цели не имеет: `z2 = z1 + RQz1` — линейная карта; при `ρ(I+RQ) > 1` вдоль выбранных направлений возможна экспоненциальная амплификация (итерации — тем более). Структурно безопаснее SRL только при: Q zero-init; остаточный гейт `g=σ(g0)`, g0≈−4; cap `‖Q(z)‖ ≤ c‖h‖`; применении к z (не к u); одном проходе; мягкой селекции.

**(д) Эффект на CE.** В пределе оптимальной оптимизации ΔCE = 0 (F(z1)). Практически — либо небольшой выигрыш от лучшей параметризации, либо вред. Единственный содержательный новый класс — **попарные взаимодействия** `u_k u_j` (сейчас логит линеен по u), релевантные для кодов с overlap 4 (различение токенов, делящих 4 бита). Оценка выигрыша не выводится аналитически — нужен эксперимент; верхняя граница ~0.2 нат, реалистично ≤0.05.

### 2.3 Задача 3 — RMS-нормализация u

**(а) Умирает ли класс сатураций.** Вариант «на позицию, по K битам»: `u_n = s·u/rms(u)`, `rms² = Σu²/K` ⇒ `max|u_n| ≤ s√K`. При K=64, s≤1.5: `|u| ≤ 12` — класс `sat` пуст. Но: (i) это не лечит ствол, если скачок h идёт вне final_norm-пути; (ii) по измеренной геометрии u уже ограничен ~45 (`|z|≤‖h‖`, `T≥0.1`), и класс сатураций **и так недостижим** — фикс лечит болезнь, которой нет в текущем чекпойнте.

**(б) Градиент и T.** Якобиан:
```
J = ∂u_n/∂u = (s/rms)·(I − ûûᵀ/K),  û = u/rms
g_u^n = Jᵀ g_u = (s/rms)·(g_u − (g_u·û)û/K)
```
радиальная компонента CE-градиента **проецируется вон** — норму u учит только скаляр s. Поскольку при `head_normalize=True` равномерный сдвиг u по битам и так неидентифицируем (добавляет Sδ к каждому логиту), нормируется только разброс u по битам; его масштаб фиксируется, а `T` (если внутри нормируемой величины) теряет скалярную часть — остаётся лишь относительная T_k. Выразительная потеря: per-position уверенность (общая острота логитов) переходит в один скаляр s; текущий T=1.27 — это и есть выученная острота, её придётся отдать s.

**(в) Стена становится избыточной.** Ключевое: обоснование стены («σ′ при |u|>17 = 0, CE-градиент умирает ~9e-14», README:406-409) **неверно для нормированного пути**: CE = logsumexp(⟨c_v,u⟩+b_v) − score_y, и `∂CE/∂u = p_k − c_yk ∈ [−1,1]` при любом |u| (проверено и аналитически, и численно: g_u std 0.30). σ(u) участвует только в `base`, а `base` выбрасывается при `head_normalize=True` (embedding.py:576-578). Значит стена — не «спасательный трос», а мягкий штраф на масштаб; при RMS-нормировке она избыточна. Что теряется при её удалении: (i) мягкий кап на разброс логитов (заменяется нормировкой); (ii) слабый aux-градиент при локально плоском CE. Ничего существенного.

**(г) Взаимодействие с bit_bias/normalize.** Нормировать **нельзя** сумму `z/T + bit_bias`: rms доминируется прайором (`rms ≈ |−2.016|`), и тогда эффективная температура зависит от среднего прайора — ловушка идентифицируемости. Правильно: `u = s·(z/T)/rms(z/T) + b_bit + bus + phantom`. При этом `s` и скалярная часть `T` дублируются — оставить одно (лучше T, per-bit, как сейчас).

### 2.4 Задача 4 — двухсторонний акцент

**(а) Что значит λ<0.** `u_k = zt_k + λ·(ℓ(r_k) − ℓ(1/K))`, `ℓ=log1p`, `r=softmax(z/T)`. При λ<0 бит с максимальным z получает отрицательный бонус — отрицательная обратная связь по разбросу u (декоррелятор/анти-сатуратор). Но динамический диапазон канала мал: при z/T std 0.81 и K=64 `r_max ≈ 0.10`, `ℓ(r_max)−ℓ(1/K) ≈ 0.094`; измеренный размах emph = 0.065 при λ=−1.25. Итого |emph| ≤ 0.05 при u std 0.8 — **канал вносит ≤1.5%**. Это не вырождение модели (вперёд он почти ничего не делает) и не полезный режим — это шум канала: Adam сдвинул λ с +1 до −1.25, потому что градиент по λ — сумма по битам `Σ_k (ℓ(r_k)−c)·g_u,k`, где слагаемые почти сокращаются.

**(б) Идентифицируемость.** `λ = φ(a) − φ(b)` (softplus) делает знак явным, но **не создаёт сигнал**: пока r почти равномерен, эффект остаётся ~1%, и оба параметра продолжат дрейфовать. Per-bit strength `g_k` (64 параметра): градиент каждого `∂/∂g_k = (ℓ(r_k)−c)·g_u,k` — **свой** для бита, разброс r по битам реален (r_max/r_min ~ e^{2·2.2}), поэтому 64 параметра идентифицируемы, а глобальный знак не может «молча перевернуться» (нет одного общего знака). Инициализация `g_k = λ_current = −1.2495` даёт **бит-в-бит тот же forward**.

**(в) Цена для чекпойнта.** 64 параметра; форма `(1,) → (64,)` требует шима в `migrate_state_dict` (core/migrate.py:31-85 уже умеет prefix-pad/reshape-миграции). Forward идентичен; Adam-моменты для нового вектора свежие → короткий транзиент. Переобучение не нужно, резюм с `best.pt` возможен.

## 4. Режимы отказа и риски

1. **Расширение readout**: полная несовместимость с чекпойнтом (code_fp), 7315 шагов и unigram-прогресс в мусор; выигрыш под вопросом. Риск высокий, обратимости нет.
2. **Двухпроходная голова**: (i) информационный ноль (доказано) — риск потратить бюджет на перепараметризацию; (ii) self-confirmation с обучаемым Q без cap — структурный аналог SRL (ce 11→91); (iii) удвоение графа головы по памяти.
3. **RMS(u)**: потеря per-position остроты логитов (её несёт T); риск замедлить именно то, что сейчас учится (униграмма через token_bias — правда, он вне нормировки, но код-путь и logZ зависят от масштаба); плюс лечение несуществующей сатурации.
4. **Per-bit g_k**: 64 новых параметра без истории Adam → краткий транзиент; риск, что канал так и останется мёртвым (тогда его надо удалять, а не тюнить).
5. **Общий риск**: все четыре предложения мотивированы спайками, чьи числа не воспроизводятся на текущей геометрии; без live-захвата есть шанс «починить» не то.

## 6. Тесты-фальсификаторы

**T1 (полоса):**
- F1-A: head-only обучение 1M токенов. Если `CE(head-only) ≥ CE(bias-only) − 0.05` на отложенном окне → z-канал неинформативен, расширять нельзя.
- F1-B: разморозка readout (λ⁻²→1), 2k шагов. Если val не улучшился ≥0.05 и std(readout) не сдвинулся ≥5% → полоса не при чём. Если улучшился ≥0.15 → readout был бутылочником, и только тогда тестировать K=128.
- F1-C: заменить readout на свежий случайный ортонормированный; head-only. Если CE совпадает с обученным (±0.02) → геометрия зондов не важна, расширение бесполезно.
- F1-D (оракул): обучить линейный `W(64×2560)` на замороженных состояниях. Если оракул CE ≤ 7.0, а текущий код-путь 12.8 → информация в стволе есть, проблема в обучении readout; если оракул ≈ bias-only → информации нет, и расширение не поможет.

**T2 (многопроходность):**
- F2-A: held-out, ΔCE = CE(2 pass) − CE(1 pass) ≥ −0.03 нат за 2k шагов → откат.
- F2-B: one-pass с эквивалентной нелинейностью (per-bit MLP той же ёмкости). Если |ΔCE| ≤ 0.01 → второй проход ничего не добавляет → не делать.
- F2-C: мониторинг `‖h2−h‖/‖h‖ ≤ 0.2` и Jaccard(top-k) между соседними позициями > 0.5; нарушение → hard-селекция = шум.
- F2-D: 3 итерации refine; если `‖u‖` растёт >20% → структурная SRL-подобная положительная связь → немедленный откат.

**T3 (RMS):**
- F3-A (premise): дамп `_last_u`, `‖h‖`, `log_temp` на каждом шаге/аномалии. Если `max|u| ≤ 512` (доказуемая граница) — wall=3541 не из этого пути; телеметрию чинить в первую очередь, u не трогать.
- F3-B: A/B 2k шагов. Если val хуже контроля на >0.1 нат или скорость роста std(token_bias) падает >20% → откат.
- F3-C: при RMS-нормировке выключить `head_u_wall`; если CE не изменился (±шум) за 2k → стена была избыточна.
- F3-D (острота): на замороженном чекпойнте прогнать CE как функцию глобального масштаба α·u, α∈{0.5,1,2}. Если CE(α) плоский — нормировка ничего не теряет; если CE(1.5·u) резко хуже — масштаб используется.

**T4 (акцент):**
- F4-A: `E|emph| / std(u)` < 5% (измерено 1.5%) → не тюнить λ; либо удалить канал, либо шарпнуть r.
- F4-B: per-bit `g_k`, 2k шагов. Если `std(g_k) < 0.05` и канал по-прежнему <2% → удалить акцент совсем.
- F4-C: `r = softmax(z·τ_e)`, τ_e обучаемая. Если τ_e остаётся ≈1 и эффект <5% → канал не нужен.
- F4-D: стабильность знака: >1 смены знака при эффекте <5% → знак — шум.

## 7. Вердикты

1. **Полоса 64→128→256: переформулировать.** Сначала F1-A/F1-D: измерить, несёт ли z условную информацию вообще, и не является ли readout замороженным бутылочником (F1-B). Только если F1-B/F1-D покажут, что информация есть и readout — узкое место, обсуждать K=128 (с полным ре-раном, не резюмом).
2. **Многопроходная голова: не делать в предложенном виде.** Алгебраически `z2 = F(z1)` — нулевой информационный выигрыш; риск self-confirmation как у SRL. Полезные переформулировки: (а) вторая независимая матрица чтения (это T1); (б) попарные члены в логитах; (в) использовать уже существующий фантомный канал.
3. **RMS-нормализация u: не делать как фикс спайков.** Диагноз не подтверждается. Приоритет — F3-A (захват).
4. **Двухсторонний акцент: не softplus, а per-bit `g_k` (или удалить канал).** Знак λ — шум мёртвого канала (эффект ≤1.5%). Per-bit strength идентифицируем, forward-идентичен при `g_k = −1.2495`, стоит 64 параметра + шим миграции.

**Неопределённости:** (i) происхождение чисел sat=1.0/wall=3541 — до live-захвата выводы о «спайках головы» условны; (ii) реальная достижимая CE код-пути при свободном readout (F1-A/D); (iii) вклад попарных членов; (iv) цена RMS для скорости изучения униграммы; (v) насколько финальный `final_norm` защищает голову в реальном train-цикле. Отдельно: в чекпойнте 212.1M обучаемых параметров (+176.2M буферов), а не «723M».
