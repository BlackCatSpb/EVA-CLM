# Зона 1 — Токены → коды → эмбеддинг → h₀

**Агент:** 1 из 6 (нерушимая цепочка, `docs/analysis/CHAIN.md`).
**Дерево:** commit `362a224` (M53e), torch 2.13.0+cpu, Python 3.14.6, Windows.
**Вход зоны:** `tokens` (B,L) `int64`, значения 0..vocab−1.
**Выход зоны:** `h₀` (B,L,D) + контракт кодового пространства (коды, basis, prior, readout).
**Предыдущего отчёта нет** — зона 1 выбрана точкой входа: токены это единственный
внешний сигнал модели, все последующие величины производны от них.

**Методика (правило полигона соблюдено).** Продакшн-модель не инстанцировалась,
чекпойнты не грузились. Анализ — чтение кода (`file:строка`). Вычисления выполнены

помечены **[audit 02a]** — это измерения аудита `docs/audit/02a_code_geometry.md`,

## 1. Граница зоны и входной контракт

### 1.1 Точка входа (обоснование)

Цепочка зон (`CHAIN.md:27-34`) начинается с токенов. Проверка фактического
потока обучения:

```
scripts/train.py:501   with autocast('cuda', enabled=use_amp):
scripts/train.py:502       h = model.embed_tokens(x)          # ← ЗОНА 1
scripts/train.py:503   out, state, gs, _ = model(h, state, ...) # ← ЗОНА 2+
scripts/train.py:507   model.observe_output(model.lm_head(out))  # salience (1-step delay)
scripts/train.py:508   ce_loss, aux_dict = model.compute_losses(out, y, h_emb=h)
```

`EVAStack.embed_tokens` — тонкая обёртка: `stack.py:982-984`
`return self.embed(tokens)`. Следовательно, граница зоны 1 — выход
`PartitionedEmbedding.forward` (`core/embedding.py:133-171`). Всё, что происходит
в `EVAStack.forward` до блока 0 (инъекция bridge, `stack.py:537-541`), — уже зона 2,
но см. §3.3 о том, что это модифицирует h₀ до первого блока.

### 1.2 Что именно приходит (контракт данных)

- Тип/форма: `tokens` (B,L) `torch.int64` (uint16 memmap → `.long()`:
  `train.py:46-74`).
- Диапазон: данные физически uint16 → 0..65535; путь данных **падает громко**,
  если id ≥ vocab (`train.py:61-66`, B7-фикс: раньше был молчаливый `np.clip`).
  PAD=0, EOS=2; `mask = targets != 0` (`core/losses.py:36`), `mask_eos=False`
  (`config.py:27`) — EOS обучается.
- Позиции: никакого позиционного сигнала в токенах нет; RoPE на эмбеддинге
  отключён и вообще запрещён (`config.py:108`, `config.py:463-466`), позиции
  входят только через ствол (conv/scan, зона 2).
- Раскладка: `PartitionedEmbedding.forward` требует строго 2D — `B, L =
  tokens.shape` (`embedding.py:161`); 1D-тензор падает **[mini-прогон]**.

## 2. Математика зоны

### 2.1 Кодовое пространство

Диспетчер (`vsa_utils.py:119-125`):

```python
def build_codes(cfg):
    if cfg.codebook == 'twin_free':
        return twin_free_codes(cfg.vocab, K=cfg.code_dim, S=cfg.code_sparsity)
    return sparse_block_codes(cfg.vocab, K=cfg.code_dim, S=cfg.code_sparsity)
```

**Legacy `sparse_block_codes` (`vsa_utils.py:128-162`)** — комбинадическая система
счисления + фиксированная перестановка:

```python
total = C(K, S)                                   # C(32,6) = 906 192
perm  = torch.randperm(total, generator=Generator().manual_seed(42))
idx   = perm[v]
for i = S..1:                                     # комбинадическое разложение idx
    c = i-1; while C(c+1, i) <= n: c += 1
    codes[v, c] = 1; n -= C(c, i)
```

Ровно S единиц на код, коды не повторяются (биекция v ↔ idx). Баланс бит —
**приближённый**: берутся первые `vocab` элементов случайной перестановки всего
пула, поэтому частоты бит флуктуируют как у случайного подмножества.

**`twin_free_codes` (`vsa_utils.py:64-116`)** — жадная упаковка constant-weight
кодов с ограничением попарного пересечения `max_overlap = S−2`:

```python
cand = torch.rand(batch, K, generator=g).argsort(dim=1)[:, :S]   # batch=2048, seed=42
ok   = (cand @ acc.T).max(dim=1).values <= max_overlap           # скрининг чанками 4096
# + внутрибатчевый жадный отсев конфликтов; >30 пустых раундов -> ValueError
```

Если пул не вмещает vocab — громкий `ValueError`; `C(32,6)` не вмещает 65536 при
overlap ≤ 4 (`vsa_utils.py:77-79`), поэтому twin_free требует `code_dim ≥ 64`
(валидация `config.py:470-473`).

**Точные числа (K=64, S=6, V=65536, twin_free) [audit 02a:55-88, 512-553]:**

**Legacy (K=32, S=6, V=65536) [audit 02a:462-464, 531]:** C(32,6)=906 192
(занято 7.23 %), вес строки 6, sha256 `98fed2eb…`, колонки сбалансированы
(colw 11 957–12 505). Пул **не гарантирует** d_H ≥ 4: у случайного подмножества
ожидаемое число «twins» (пересечение 5, d_H = 2):

```
E[twins] = C(V,2) · S(K−S) / (C(K,S)−1) = C(65536,2)·156/906191 ≈ 3.70·10⁵
          → в среднем ≈ 11.3 d_H=2-соперника на каждый код
```

Комментарий `vsa_utils.py:66-67` цитирует «215 504 pairs at K=32/S=6/65 536» — это
число соответствует **старому vocab=50 000** (`C(50000,2)·156/906192 ≈ 215 183`),
а не текущему 65 536. При V=65 536 ожидание ≈ 3.7·10⁵ — расхождение в 1.7×,
важно для оценки margin legacy-книги.

**Энтропия [формула].** Код — детерминированная функция id; при равномерных
токенах H(код) = log₂ 65 536 = 16 бит. Маргинальные энтропии бит:

```
legacy:   H₂(0.1875)  = 0.6962 бит/бит × 32 = 22.28 бит
twin_free:H₂(0.09375) = 0.4489 бит/бит × 64 = 28.73 бит
ёмкость:  log₂ C(32,6) = 19.79 бит;  log₂ C(64,6) = 26.16 бит
```

Сумма маргиналов сильно больше 16 бит — коды имеют ровно S активных бит
(сильная отрицательная корреляция бит); энтропия кодовой книги как таковой
(равномерно по пулу) — 19.79/26.16 бит.

**Коллизии и co-occurrence.** Коллизий нет ни у одного билдера (биекция).
Legacy: twin-пары d_H=2 (см. выше). Twin_free: пары с overlap ≥ 5 отсутствуют
точно, ближайший класс — d_H=4 (711 504 пары), у каждой пары сертифицированный
init-отрыв `score_true − score_rival` в u-единицах: **min +0.2993, p1 +0.542,
mean +0.768, доля правильного порядка 1.000000** [audit 02a:81-88]. Это
«бюджет margin» идентичности: шумовая эрозия per-bit разделения более чем на
~80 % от 0.377 (см. ниже) переворачивает ближайших соседей.

**Prior (`prop`) и head-инициализация.** `SigmoidCodedHead` считает
эмпирическую частоту бит и ставит `bit_bias` в логит-масштабе
(`embedding.py:278-284`):

```python
prop = codes.mean(dim=0)                      # (K,), persistent buffer _prop
_p   = prop.clamp(1e-7, 1 - 1e-7)
bit_bias = log(_p / (1 - _p))                 # = logit(p̄_k)
```

Математическое замечание (mean-field): `bit_bias` — произведение независимых
бернуллиевых приоров, тогда как истинное распределение кодов сосредоточено на
слое ровно S активных бит. При независимых битах с p = S/K вероятность попасть
в валидный код:

```
P(ровно S активных) = C(K,S)·p^S·(1−p)^(K−S)
  K=64,S=6: 74 974 368·0.09375⁶·0.90625⁵⁸ ≈ 0.168
  K=32,S=6:    906 192·0.1875⁶·0.8125²⁶ ≈ 0.178
```

т.е. ~83 % массы mean-field приора лежит вне кодовой книги. На production
(`head_normalize=True`) это не ломает распределение (log-softmax по V нормирует),
но задаёт масштаб `u` и «мягкость» приора — важно для зоны 5.

**OOV (клэмп), `embedding.py:134-148`:**

```python
max_id = codes.shape[0] - 1                    # = vocab − 1 = 65535
if (tokens > max_id).any(): warnings.warn(...) # один раз за жизнь модуля
tokens = tokens.clamp(0, max_id)
```

Следствия: отрицательные id → строка 0 (PAD); id ≥ vocab (зарезервированные
reasoning-токены THINK..END ≥ 65536, упомянутые в комментарии M9
`embedding.py:137-139`) → строка 65535. Класса `ReasoningTokens` в дереве нет
(grep — только комментарий), т.е. это будущая, а не текущая опасность. В
кодовой книге нет «зарезервированной геометрии»: строки 0, 1, 2, 65532…65535 —
обычные коды веса 6 [audit 02a:458-484]. На пути данных клэмп недостижим: он
нужен только генерации/новым спец-токенам.

**Полигон (SMALL) [mini-прогон]:** C(16,4) = 1820 = vocab **точно**, поэтому
книга — полное множество 4-подмножеств из 16: вес строки 4, маргиналы бит
**ровно 0.25**, max overlap = 3 (= S−1, d_H=2), 43 680 twin-пар (у каждого кода
48 соперников), ёмкость log₂ 1820 = 10.83 бит. Это **не** twin_free-режим: выводы
полигона о margin на продакшн не переносятся (см. §6).

### 2.2 Эмбеддинг: точный forward

`PartitionedEmbedding.forward` (`embedding.py:133-171`) без сокращений:

```python
# 0) границы/клэмп (см. §2.1)
c  = self.codes[tokens]                       # (B,L,K) float32, {0,1}, Σ_k = S
# 1) плотное смешивание
z  = c @ self.embed_mix                       # (B,L,K); (cM)_j = Σ_i c_i M_ij
a  = torch.sigmoid(z * self._mix_scale)       # _mix_scale = 2.0 (buffer, persistent=False)
# 2) центрирование (embed_center, по умолчанию False)
if self.embed_center:
    if self.training:                         # EMA только в train
        self._sig_mean.mul_(0.999).add_(
            a.detach().reshape(-1, K).mean(0) * 0.001)
    a = a - self._sig_mean.to(a.dtype)        # _sig_mean: (1,K), persistent=False
# 3) сегментно-адресная сумма
h0 = (a.unsqueeze(-1) * self.basis.view(1, 1, K, -1)).reshape(B, L, -1)
#    h0 = Σ_k a_k · (B_k ⊗ e_k)   — вклад бита k лежит ТОЛЬКО в сегменте k
if self._embed_rope_on:                       # недостижимо: config.py:463-466
    h0 = self.rope(h0)
```

Инициализация (`embedding.py:103-131`):

```python
embed_mix = I_K + 0.05·randn(K, K; generator seed=7)   # near-identity
_mix_scale = 2.0
basis     = _orth_rows(randn(K, d; generator seed=5))
```

Активации при init [audit 02a:263-268], вывод [формула]: для j ∈ supp(c)
`(cM)_j = 1 + 0.05·N(0,S)`, для j ∉ supp — `0.05·N(0,S)`; после `×2`:
z_active ~ 2 + 0.1·N(0,S), z_inactive ~ 0.1·N(0,S); при S=6 std(z)=0.245, что
с σ'(2)=0.105 и σ'(0)=0.25 даёт ровно наблюдаемые разбросы:

| | production K=64,S=6 [audit 02a] | mini K=16,S=4 [mini-прогон] |
|---|---|---|
| a активных | 0.8800 ± 0.0260 | 0.8745 |
| a неактивных | 0.5030 ± 0.0607 | 0.4933 |
| per-bit сигнал | 0.377 | ~0.381 |
| диапазон a | [0.2281, 0.9549] | — |

Ключевое: неактивные биты **не 0, а 0.5** — каждый из (K−S) сегментов даёт
вклад ~половины амплитуды в каждый токен; отсюда структурный common-mode.

**Норма h₀ [формула]:** basis-строки единичные, сегменты ортогональны, поэтому

```
‖h0‖² = Σ_k a_k² ≈ S·σ(2)² + (K−S)·σ(0)²
production: 6·0.7744 + 58·0.2530 = 19.32 → ‖h0‖ ≈ 4.40, RMS = 4.40/√2560 ≈ 0.0869
legacy K=32: 6·0.7744 + 26·0.2530 = 11.22 → ‖h0‖ ≈ 3.35, RMS ≈ 0.0523
mini K=16:   4·0.7744 + 12·0.2530 =  6.13 → ‖h0‖ ≈ 2.48, RMS ≈ 0.1095
```

Мини-прогон: ‖h₀‖ = 2.4507 (min 2.367, max 2.517), RMS/dim 0.1083 — сходится с
формулой в 1 %. По токенам норма варьируется мало (std ~3 %): DC доминирует.

**Common-mode [audit 02a:258-296]:** средняя попарная косинусная близость
эмбеддингов 0.9512 (медиана 0.9502, σ 0.0095), доля энергии общей моды
‖μ‖²/E‖e‖² = 95.11 % (первая PC — 95.13 %). Mini: pair-cos 0.9234, common share
0.9239 **[mini-прогон]**. То есть на старте 95 % эмбеддинга — один и тот же
вектор; в ствол (conv/mirror/bridge/memory) это уходит как есть
(`embed_center=False` в config и в cell-4).

**embed_center (`embedding.py:115-120, 152-160`).** Центрируются не коды, а
плотные сигмоид-активации: вычитается `_sig_mean` — среднее `a` по фиксированной
выборке `codes[:8192]` (12.5 % книги на production) при init, далее EMA
(0.999/0.001) по текущему батчу **только в training**. Измерено [audit 02a]:
после центрирования pair-cos 0.0002 (σ 0.1888), PC1 9.32 %, cond 1447, roundtrip
сохраняется 1.000 (сдвиг поглощается головой). Mini-прогон подтверждает:
pair-cos −0.0005, roundtrip top-1 = 1.0, но ‖h₀‖ падает 2.45 → 0.675.
Буфер `_sig_mean` **non-persistent** — при resume он пересчитывается от
fresh-init `embed_mix`, а не от загруженного, и EMA сходится ~1000 шагов
(дремлющий дефект, пока флаг False).

**dtype/AMP/режимы.** Коды — float32 (буфер), токены int64. Под `autocast`
(`train.py:501-502` — autocast обёрнут **только вокруг** `embed_tokens`, ствол
идёт в fp32) `c @ embed_mix` может исполниться в fp16/bf16, но внешнее
произведение `a ⊗ basis` — elementwise mul с fp32-параметром, промоутится в
fp32; комментарий `embedding.py:162` фиксирует, что einsum заменён на внешнее
произведение именно ради AMP-стабильности. `use_amp=False` по умолчанию
(`config.py:58`). Режимных различий в forward нет, кроме EMA `_sig_mean`
(train-only) и одноразового warning.

### 2.3 Readout головы как контракт

**Тайинг.** `EVAStack` строит голову с `embed_basis=self.embed.basis`
(`stack.py:33`), и `SigmoidCodedHead.__init__` присваивает
`self.readout = embed_basis` (`embedding.py:273-274`) — это **тот же объект
`nn.Parameter`**, одна геометрия на кодирование и декодирование, один градиент
с двух путей.

**`_orth_rows` (`embedding.py:175-185`) — точный код:**

```python
K, d = A.shape
if K <= d:
    Q, _ = torch.linalg.qr(A.T)      # столбцы Q ортонормированы (d×K)
    A = Q.T.contiguous()             # строки A ортонормированы: A Aᵀ = I_K
A = A / A.norm(dim=1, keepdim=True).clamp_min(1e-8)
return A * gain**0.5                 # gain = 1.0 по умолчанию
```

Фактическое поведение по геометриям:

| Геометрия | Ветка | Ранг матрицы basis (K,d) | Граматрица |
|---|---|---|---|
| config default K=32,d=128 | QR | 32 | R Rᵀ = I₃₂ (mini offdiag 1e-7) |
| production K=64,d=40 | **QR пропущен** | 40 | строки единичные, off-diag ≠ 0 (~N(0,1/40), σ≈0.16) |
| mini K=16,d=32 | QR | 16 | R Rᵀ = I₁₆ [mini-прогон: offdiag max 1e-7, row norms 1.0] |

При K=64 > d=40 ранг basis как матрицы 40, но **карта чтения** h → z
(блочно-диагональная, по одному скаляру на сегмент) имеет ранг ровно K=64,
потому что строки живут в непересекающихся сегментах. Измеренная изометрия
[audit 02a:242-248]: `z_k = a_k·‖B_k‖² = a_k` точно (сегментные фреймы
дизъюнктны), поэтому неортогональность строк при K>d на roundtrip не влияет
(top-1/top-5 = 1.0000/1.0000 на 8192 corpus-weighted + 8192 uniform + 1000
hot id). Если бы readout читал чужие сегменты, cross-talk ~0.16 на пару — но
конструкция это исключает.

**Что голова видит и что — нет (количественно, production):**

```python
h_g = h.reshape(B, L, K, d)
z   = (h_g * readout).sum(-1)                 # z_k = <h_сегмент_k, B_k>, (B,L,K)
e_l = h - (z.unsqueeze(-1) * readout).reshape(B, L, D)   # лакуна, embedding.py:371
```

| | Величина | Размерность | Доля D=2560 |
|---|---|---|---|
| Видит (known bits) | z — по одному скаляру на сегмент, span{B_k ⊗ e_k} | K = 64 | 2.5 % |
| Не видит (лакуна e_l) | ортогональное дополнение к readout-направлениям | D − K = 2496 | 97.5 % |

- На h₀ **e_l = 0 точно** (h₀ построен из тех же B_k); после ствола h выходит из
  этого подпространства, и относительная лакуна `ell = ‖e_l‖/‖h‖` для реалистичных
  состояний ≈ 0.97 (комментарий M55b, `embedding.py:303-307`).
- Лакуну читает отдельный phantom-basis: `_orth_rows(randn(Kp=32, D))` —
  32 ортонормированных направления **в полном D** (Kp=32 ≤ D, QR-ветка),
  `phantom_mix` нулевой → forward на init бит-в-бит равен only-known-bits
  (`embedding.py:294-319, 445-486`).
- Ранг «identity-канала» всей модели: **rank(embedding manifold) = 64 из 2560**
  (2496 координат h₀ тождественно нулевые, потому что в сегменте используется
  только span(B_k), а не весь R^d) [audit 02a:250-256].

**Цепочка логитов (контракт зоны 1 → 5), `embedding.py:345-379, 500-540`:**

```python
T = exp(log_temp); T += (T.clamp(0.1,10) - T).detach()      # ST-clamp
z_data = z / T
zt = z_data + bit_bias (+ bus_bias)                          # (B,L,K)
rel = softmax(z_data)                                        # emph_logits, tau=1
u   = zt + emphasis_gain·(log1p(rel) − log1p(1/K))           # hybrid_gate, log=True
base = Σ_k logσ(−u_k)
# phantom (M52b): u += p @ phantom_mix.T, p = tanh(e_in @ phantom_basis.T)·g(ell_rel)
logits_v = Σ_k u_k c_{vk} + (base if not normalize) + token_bias_v
if temper: logits /= (1 + 0.5·χ), χ = relu(0.3 − cos(h_implied, mem_dir))
if normalize: logits −= logsumexp_v(logits)
```

Замечание: `S` в `SigmoidCodedHead` (`embedding.py:266`) нигде не потребляется —
мёртвое поле в sigmoid-ветке [audit 02a:329-333].

### 2.4 Геометрия h₀ и связь с последующими нормами

| Величина | production K=64 | legacy K=32 | mini K=16 |
|---|---|---|---|
| ‖h₀‖ (аналит./изм.) | ≈4.40 | ≈3.35 | 2.4507 изм. |
| RMS на dim | ≈0.0869 | ≈0.0523 | 0.1083 изм. |
| pair-cos (изм.) | 0.9512 | — | 0.9234 |
| common-mode energy | 95.11 % | — | 92.39 % |
| rank / «нулевых» dim | 64 / 2496 | 32 / 4064 | 16 / 496 |
| видимая размерность у головы | 64 | 32 | 16 |

Связь с нормами дальше по потоку:
- **M31 (per-branch pre-LN, `block.py:449-464`):** ветви блока читают `LN(h)`,
  т.е. масштаб h₀ (~0.087 RMS) не важен для входов ветвей — LN нормирует; сам
  поток остаётся истинным residual-аккумулятором и несёт DC/структуру h₀ как есть.
- **M50 (fuse, `stack.py:376-386`, `config.py:439`):** `stream_cap=1e3`
  (scale-инвариантный amax-cap) срабатывает на «здоровых» стримах 30–70; h₀ ≈ 4.4
  на порядок ниже порога. Масштаб 1e20 → inf → rsqrt(inf)=0 (историческая
  deadlock-авария) к зоне 1 отношения не имеет, но h₀ — точка отсчёта шкалы.
- **Финальная норма (`stack.py:710-715`):** перед головой h перемасштабируется
  `final_norm_w · ĥ · rsqrt(mean(ĥ²)+1e-7)`, где `ĥ = h/max|h|`; на выходе зоны 2
  RMS(h) ≈ 1, т.е. голове достаётся не h₀-шкала. Границы шкал: h₀ (4.4) → поток
  после блоков (30–70, cap 1e3) → final_norm (~1).

### 2.5 Градиентные пути, обучаемое/буферы, миграции

**Обучаемые параметры зоны (production K=64, d=40, V=65536):**

**Буферы (не обучаются):** `embed.codes` (V,K) `persistent=False` — не в
`state_dict` (audit F2A-02: `state_dict has embed.codes: False`); `_mix_scale`
(1,) non-persistent; `_sig_mean` (1,K) non-persistent; `lm_head.codes`
non-persistent; `lm_head._prop` (K,) **persistent** (но используется только для
init `bit_bias`); `ell_ema`, счётчики SRL/phantom — non-persistent. Коды не
получают градиента (индексация int64); `embed_mix` получает градиент через
`c @ M` (c — константа, M — параметр).

**Тайинг:** `basis` — один Parameter, градиенты копятся с двух путей
(эмбеддинг-внешнее-произведение и readout-скалярное-произведение). Это делает
зону 1 и зону 5 неразделимыми по оптимизации: менять LR readout — менять
эмбеддинг.

**`log_probs_for_target` (`embedding.py:542-570`):** при `normalize=True`
(production) вызывает `forward` и gather — CE идёт по нормированному
log-softmax; при `normalize=False` считает факторизованный скор
`Σ_k [c_k logσ(u_k) + (1−c_k) logσ(−u_k)] + token_bias[t]`, что тождественно
`logit_t` из forward (т.к. `logσ(u) − logσ(−u) = u`) — ветки согласованы.

**Миграции (`core/migrate.py`).** Зона 1 **не мигрируется вообще**: функции
`migrate_state_dict` трогают только `bind.W_out` (46-58), `bind_coh_gate=0`
(62-65), `freq_scale=1.0` (66-69), удаляют `thinking_head.*`/`memory_bank.l3.*`
(76-79), режут fusion 4D→3D (80-89), удаляют legacy V×D-проекции logit_cache
(99-116) и переназначают `cache_gate` bias → −10 (118-125). Ни один тензор
`embed.*`/`lm_head.*` не мигрируется. Защита вместо миграции — B8
(`core/training_control.py:419-465`): `codebook_fingerprint` (sha256 по
(V,K)-блоке, формат `VxK-16hex`) сохраняется в чекпойнт (`train.py:273,648`,
ноутбук:782) и `verify_identity_resume` **падает RuntimeError** при
shape-mismatch любого `embed.*/lm_head.*/final_norm*` или при расхождении
fingerprint (при старом чекпойнте без `code_fp` — предупреждение и проверка
только форм). Это закрывает F2A-02/F2A-03-дыру, но контракт «коды = f(cfg,
seed, алгоритм)» остаётся неявным: seed 42, batch 2048, чанк 4096, правило
отсева — не поля конфига.

**Известный латентный дефект** [audit 02a F2A-12]: `core/compression.py:226-256`
при декомпрессии пересобирает коды через `sparse_block_codes` (legacy) даже для
twin_free-моделей; сегодня инертен (коды non-persistent), но станет тихой
подменой книги, если коды сделают persistent.

### 2.6 Сводка инвариантов зоны

1. `Σ_k codes[v,k] = S` для всех v; коды уникальны; `vocab ≤ C(K,S)`.
2. `h0 = Σ_k a_k B_k⊗e_k` — вклад бита только в свой сегмент; `z_k = a_k` при
   тайном readout; `e_l(h0) = 0`.
3. `rank(embedding manifold) = K`; `D−K` координат h₀ равны нулю.
4. Init: `embed_mix = I + 0.05·N(seed 7)`, `basis` — единичные строки
   (QR-ортонормированные при K ≤ d), `bit_bias = logit(p̄)`.
5. Roundtrip `id → h₀ → argmax` = 1.0000 на init (production [audit 02a:235-240],
   mini [mini-прогон]); сертифицированный margin ближайших кодов min +0.2993
   u-единиц (twin_free).
6. `embed_center=False` по умолчанию: common-mode 95.11 % уходит в ствол.

## 3. Что зона делает с входным контрактом

### 3.1 Проверка/преобразование

- **Range:** clamp в [0, vocab−1] с одноразовым `RuntimeWarning`
  (`embedding.py:136-148`); данные до этого уже проверены громко
  (`train.py:61-66`) — клэмп это guard, не fold.
- **Layout:** требует (B,L) ровно; 1D падает (проверено [mini-прогон]).
- **Детерминизм:** `build_codes` — чистая функция (cfg, алгоритм, seed); кэш
  `_CODES_CACHE` возвращает клон; fingerprint фиксируется в чекпойнте (B8).
- **OOV:** id ≥ vocab коллапсируют в строку 65535 (необратимо, см. §2.1).

### 3.2 Что теряется на входе

- Вся позиционная информация: h₀ позиционно-инвариантен (RoPE запрещён
  `config.py:463-466`; conv/scan читают ось времени уже в зоне 2).
- Идентичность токена за пределами span{B_k⊗e_k}: 2496 координат h₀ — нули,
  а после ствола всё, что попадает в ортогональное дополнение, невидимо
  голове (лакуна) — это by design, но именно там живёт весь «некодовый» смысл.
- Токены ≥ vocab не различимы (общий клэмп).

### 3.3 Стык зоны 1 → зоны 2

`EVAStack.forward` получает уже готовый h и **до блока 0** делает:
- `bridge.inject_layer(0, h, ...)` (`stack.py:537-541`) — на init это
  тождество (`stream_log_scale=tanh(0)=0`, `bridge_stream` нулевой,
  `bridge.py:85-93,157-169`), после прогрева — нет; «чистый h₀» существует
  только в момент выхода зоны 1.
- `memory_bank` (по умолчанию `memory_bank=False`, `config.py:348`) — не
  участвует.
- **Декларированный «two-ended read» мёртв:** `h_emb` передаётся в
  `compute_losses` (`train.py:508`, `stack.py:1260-1269`), но в
  `core/losses.py` он присутствует только в сигнатуре и docstring
  (`losses.py:10,13`); grep по телу — 0 использований. Голова видит только
  `out` (h после ствола и final_norm). Агент 5 не должен рассчитывать на
  h_emb-канал.

## 6. Открытые вопросы и риски для следующего агента

1. **Какая геометрия?** `config.py`+`scripts/train.py` дают legacy K=32/D=4096,
   README/ноутбук — twin_free K=64/D=2560; CLI не умеет задавать code-геометрию,
   `--head` не потребляется. Агент 2 должен явно указать K/S/codebook своего
   анализа, иначе выводы о сегментной структуре могут не соответствовать коду.
2. **Margin-бюджет эродирует.** На единственном чекпойнте (legacy, 1045 шагов)
   нормы basis-строк упали 1.000 → [0.5146, 0.6423] (квадраты 0.26–0.41, разброс
   1.56×) [audit 02a F2A-09]: margin ближайших кодов сжимается ~2.4–3.8×. Каналы
   мониторинга — `‖B_k‖² min/max spread` и пара-маргин d_H=4; их никто не
   логирует. Риск: тихая потеря identity-канала на длинном обучении.
3. **Common-mode 95 %.** В ствол с шага 0 уходит один общий вектор (cos 0.9512);
   `embed_center` лечит это (cos → 0.000), но default False, это geometry-change
   только для fresh run, и взаимодействие с head-приором (`bit_bias`) после
   центрирования не откалибровано [audit 02a F2A-06]. Решение — за зонами 2/5.
4. **Полигон не равен продакшну по кодам:** SMALL насыщает C(16,4)=1820 (маргиналы
   ровно 0.25, max overlap 3 = S−1, 48 twins/код). Любые выводы мини-прогонов о
   margin/recall к twin_free K=64/S=6 не переносятся; для margin-экспериментов
   нужна честная мини-книга (например, legacy K=32/S=6/vocab малый).
5. **Resume-контракт кодов** держится на fingerprint (B8), но алгоритм/seed не
   в cfg; старые чекпойнты без `code_fp` проверяются только по формам;
   `compression.py` пересобирает twin_free-книгу legacy-билдером (латентно).
6. **OOV:** id ≥ 65536 (reasoning-токены) молча клэмпятся в строку 65535; класса
   токенов в дереве нет — при появлении генерации спец-токенов нужен отдельный
   канал (не token id).
7. **`_sig_mean` при resume** (если `embed_center=True`): non-persistent буфер
   стартует от fresh-init `embed_mix` и переучивается ~1000 шагов — временный
   сдвиг h₀ после resume; стоит проверить в зоне 6.
8. **`h_emb` мёртв** — «двухконечное чтение» не реализовано; не закладывать в
   анализ головы.
9. **AMP-стык:** под `use_amp` эмбеддинг идёт под autocast, а ствол — нет
   (`train.py:501-503`); dtype h₀ на границе может быть смешанным (mul промоутит
   в fp32) — проверить при включённом AMP.
10. **Лакуна/phantom:** 2496 невидимых измерений — это не «шум», а единственный
    канал для нового смысла (M52b/M54); ствол и память пишут туда, и именно там
    работает банк фантомов. Для зоны 2: любые операции, симметричные по всем
    D, автоматически влияют на лакуну; для зоны 5: относительная лакуна
    само-калибруется EMA (0.99) и в eval не дрейфует.
