# FINAL REPORT — сквозной математический анализ EVA-CLM (M57)

Составлен по шести отчётам цепочки (`zone_1..zone_6`), каждый из которых обязан был
учесть выводы предыдущего. Здесь — синтез: сквозной поток, подтверждённые факты,
обрывы проброса, реестр рисков и приоритеты.

---

## 1. Сквозной поток (что реально течёт от токена до обновления весов)

```
tokens (B,L) int64
  │  Z1: codes[token] ∈ {0,1}^K (вес S, ЗАМОРОЖЕНЫ, non-persistent буфер)
  ▼
a = σ(2·c·M)  →  h₀ = Σₖ aₖ·Bₖ⊗eₖ            ‖h₀‖≈4.40, RMS≈0.087, DC 95.11%
  │  readout ≡ basis (тай); голова видит ровно K=64 из D=2560 (2.5%)
  │  лакуна = ортогональное дополнение (2496 dim) — уже на h₀ e_l=1.2e-7
  ▼
Блок ×24 (Z2): h ← h + Σ веток; все ветки читают _ln(h) (unit-RMS, M31)
  порядок: conv → bind → VSA → mirror → enhanced → VPM → spectral → MLP
  шкала потока задаётся VSA-чтением (w_q_mu ~ N(0,1) без 1/√D): 2.45 → 66.9 → 83.5
  лакуна заливается стволом с блока 0: 0.951 (после блока 1 — 0.943)
  M50 (1e3) и M51 (1e4) на init НЕ срабатывают; M50 — после блока, до UCL
  ▼
Память (Z4): UCL-инъекция (после блока 0, ≤25% нормы) · банк L1/L2 (пишет 24×/форвард)
  · logit cache (R1: 5% compressed-logits) · intent-шина (bus_bias — per-bit stencil)
  · reasoning (после final_norm, ramp 1−exp(−t/1000))
  ▼
final_norm (amax-safe, RMS≈1) → reasoning → augment (gate≈4.5e-5)
  ▼
Голова (Z5): z=⟨h,R⟩; zt=z/T+bit_bias(+bus_bias); r=softmax(z/T); u=zt+λ(log1p r−c)
  logits = u@Cᵀ + token_bias − logsumexp;  лакуна ℓ≈0.971 → known-share≈0.24
  каналы M52–M56: стенка (|u|>6), фантомы (гейт 0.05), SRL (диагностика), temper (3D)
  ▼
Лосс (Z6): CE (surprisal 0.3) + ~24 aux; LossBalancer = per-param sign-mask +
  кламп ‖Δ_aux‖≤‖g_CE‖; AGC; τ-LLRD; depth; (watchdog — НЕ вызывается)
  ▼
optimizer.step() → release_step_graph() → чекпойнт best.pt
```

**Замкнутость контура к Z1**: разомкнута по идентичности — коды заморожены, обучаются
только `basis/embed_mix/bit_bias/token_bias/phantom_*`. Это осознанный дизайн
(композиционность важнее подгонки кодов), но означает: «новые концепты» не могут
появиться в кодовой книге без внешнего механизма (M55, который пока без потребителя).

## 2. Подтверждённые факты (по зонам)

**Z1. Коды и вход.** Три разные геометрии в дереве (config/CLI: K=32,d=128; cell-4:
twin_free K=64,d=40; полигон: K=16). Коды уникальны, d_min=4, margin min +0.2993.
`readout` — тай с `basis` эмбеддинга; при K=64,d=40 QR не выполняется (строки
единичные, ранг 40), но сегментная дизъюнктность даёт roundtrip 1.0000. Common-mode
95% уходит в ствол (embed_center=False). Эрозия basis к шагу 1045: margin [0.51,0.64].

**Z2. Ядро блока.** M31 работает: CE-градиент L0/L1 = 15.36/10.14 (было L0/L23=1.2e-8).
`exact_memory` непричинна (полная L×L, гейт открыт 0.599/0.332). `reset_cache()` не
чистит `_traj_state`. `pen` в state-tuple вестигиален.

**Z3. Mirror.** `pen ≈ sqrt((1+α²)/k)` — не surprise, а функция α/k/pos_id
(фиксированный ±1 `_pos_id_buf` даёт 0.342 из 0.342). **`mat` — таймер, не
компетентность**: `pen_init=1.0` + `max` навсегда; симуляция даёт 0.833 ровно на
шаге 3135 — это и есть M47-«mat 0.82»; `lbg_tau=gate_tau(0.82)=0.4978` — следствие.
Маркеры M47 (`mlp_out 1400→424`, `diversity 0.6→0.08`) неспецифичны: MLP всегда видит
_ln(h), гейт меняет выход на −2.8% при maturity 0→1; свежий прогон (350/0.1, val 10.82)
— та же комбинация при лучшем качестве. Deep-слои на init почти one-hot на `help`.

**Z4. Память.** UCL: запись гейтится `mat_gate[0]<0.1` (hard-skip) И собственным
`_mature` (0.3/0.1, от resvar зеркала) — два независимых «таймера»; [mini] градиенты
записи ~9e-10 (канал почти не обучается). Банк вызывается в цикле слоёв → одно
SEP-предложение пишется ~24× за форвард; novelty-эвикция не реализована (докстринг
врёт). LBG `layer_gate` не влияет на поток. Триада в inference не восстанавливает
банк/UCL/кэш (дубли записей). `reset_cache` неполон.

**Z5. Голова.** Формула подтверждена бит-в-бит; аудит M52a воспроизведён
(corr(bit_bias,бонус)=+0.90 снят; d logsigmoid/du|₃₀=9.36e-14; стенка). Лакуна
структурна: пол ℓ=√(1−K/D)=0.9843, после ствола 0.971 → known-share≈0.24. `ph_*=0`
by design (гейт 0.05 при rel≈1.0; банк ждёт rel>1.1; `confirmed_directions()` без
потребителя — M55 не реализован). **Tempering действует только на 3D-вызовы**: CE-путь
(N,1) не проходит shape-check → CE-градиент не темперируется. Стена/`sat` слепы к
фантомам (`_last_u` пишется до `_phantom_mix`). M53d/M53e: диагностика бит-идентична,
катастрофа apply зафиксирована числами (ce_raw 11→31→78→91, sat→1.0, srl_expl→27).

**Z6. Обучение.** LossBalancer — не то, что в docstring (per-param sign-mask + кламп,
`cos/scale` мертвы). **FailureDetector полностью инертен** (`check()` не вызывается
нигде). Два разных боевых контура (train.py: AdamW, bank off, surprisal 0; ноутбук:
eva_proj, bank on, surprisal 0.3, branch 0.1, gradalign 0.3, seed 1234). Баги train.py:
B19 делит seq_len при ckpt; B15 `mlp_gate_b_init` затирает обученный гейт на resume;
`ls_mult` дважды. τ-авторитет размножен (три формы α). `token_bias` без wd.
Surprisal-разрыв train/val ×2.0–2.3.

## 5. Что подтверждено как сильное (не отменяется находками)

1. **Лакуна — структурная теорема**, а не эвристика: readout ранга K оставляет
   ровно D−K ортогональных измерений; голова математически слепа к 97.5% состояния.
   Единственный структурный читатель — `phantom_basis` (32 из 2496).
2. **Гибридный гейт чист** после M52a: мёртвый base убран, прайор снят (corr +0.90→0),
   λ обучаем, стенка даёт линейный барьер (9.4e-14→1.9e-4).
3. **Композиционная голова работает**: val 10.82 — лучший за историю проекта
   (против 11.16 прежнего и 12.91 старого прогона) при живых `sat=0`.
4. **Предохранители M50/M51/M53d держат**: там, где прежние прогоны умирали
   (2970, 1045), текущий выжил и улучшился.

## 6. Приоритеты (по убыванию отношения эффект/риск)

1. **Tempering: починить shape-check** — сейчас CE-градиент не темперируется вовсе
   (M55a работает только в 3D-вызовах). Один shape-фикс.
2. **Watchdog: включить или удалить** — FailureDetector не вызывается; при NaN
   AGC даёт «тихого зомби» до eval.
3. **train.py: три бага** (B19 seq_len при ckpt; B15 затирание гейта; ls_mult ×2) —
   иначе CLI-контур неэквивалентен ноутбуку.
4. **`mat`: перекалибровать `pen_init`** (0 или от первого наблюдения) — иначе
   readiness остаётся часами и перекрывает deep-first τ-геометрию до ~18–26k шагов.
5. **Персист состояния**: mirror-кэши, `_branch_var_ref`, `_mem_dir/bus_bias`,
   `ell_ema` — иначе холодный resume и невоспроизводимость.
6. **`reset_cache` дополнить**: `_traj_state`, `_cached_usefulness`.
7. **Банк: 24×/форвард запись** — устранить дублирование (одно предложение — один раз).
8. **UCL: оживить градиент записи** (сейчас ~9e-10) или признать его декоративным.
9. **M55: дать потребителя `confirmed_directions()`** — иначе фантом-банк навсегда
   наблюдатель (на однородных данных всплесков rel>1.1 нет by design).
10. **Логи**: телеметрия головы + aux в train.py (сейчас только ноутбук/analyze).

## 7. Ответ на исходный вопрос цепочки

Сквозной анализ показал: архитектура **математически связна там, где заявлено**
(лакуна, гейт, поток, голова), но имеет **разрывы в пробросе состояния** (10 позиций
таблицы §3) и **несколько «таймеров», названных измерениями** (`mat`, `lbg_tau`,
`_mature`). Ни один разрыв не является фатальным для текущего прогона (val 10.82 —
лучший), но каждый ограничивает то, что архитектура обещает в README. Наибольший
нереализованный потенциал — связка «лакуна → фантом → рост бит» (M55): структурно
готова (банк, лайфцикл, буферы), не подключена (нет потребителя) и не срабатывает
на однородных данных (нет всплесков новизны).
