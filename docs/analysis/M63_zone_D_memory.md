# M63 / агент D — память

> Цепочка M63 (2026-09-17). Только исследование и математика; код не правился, чекпойнты не грузились.
> Метки: [лог] — из брифа M63; [формула] — аналитика; [mini] — мини-прогоны на голых модулях (прод-геометрия `D=2560, bridge_dim=256, L1=3, L2=32`; скрипт `%TEMP%\opencode\m63_mem_probe.py`).

## 0. TL;DR

1. **Банк сейчас — не память, а обучаемый per-forward bias.** [mini] При рабочей шкале `|h|≈40–60` косинус чтения L2 между позициями `cos(r_t, r_t') = 0.9999–1.0000`, у L1 — ровно `1.0000`. Контент-адресации нет: softmax плоский (rowmax 0.063 против 0.031 uniform, и это статическое предпочтение слота, одинаковое для всех позиций).
2. **Запись не обучается вообще.** `W_k/W_v` живут внутри `@torch.no_grad()` и пишут в буферы (`memory_bank.py:207-208, 234-253`); [mini] градиенты `W_k/W_v = None`, `novelty_gate = None`. Ключи — случайные проекции, замороженные с инициализации. Content-addressable retrieval случайным ключом — лотерея 1/N.
3. **Поэтому любой предсказательный запрос (a/b/c) сам по себе не даст CE-выигрыша**: адресовать нечего, чтение и так почти константа. [mini] Даже оракульный по смыслу `h+λv` при λ=1..3 меняет rowmax внимания на `<0.0002`.
4. **`mb_scale=-0.963` и `mem_tau_reg=0` — следствие того же вырождения**: инъекция почти константна, CE-градиент к скаляру `log_scale` и к τ статистически мал; на старте он ровно нулевой из-за zero-init `fusion[-1]` (`memory_bank.py:388-390`).
5. **Вердикт:** предсказательный запрос — **переформулировать** (сначала оживить запись и геометрию скоринга); surprise-маршрутизация — **не делать сейчас**; аудит — novelty-гейт мёртв, L3-насыщение нормально, но ёмкость 8 концептов — узкое место.

## 2. Математика текущего чтения

```
s_t,i = q_t·k_i / √d,        q_t = W_q h_t,   k_i = normalize(W_k s_i)·0.5
g_t,i = σ(s_t,i)·(1 + softmax_i(s_t/τ)),      w = g / Σg
r_t   = Σ_i w_t,i v_i,        v_i = val_norm(normalize(W_v s_i)·0.5)
```
Градиент к запросу: `∂L/∂q = Σ_i (∂L/∂w_i)·(∂w_i/∂s_i)·k_i/√d`, где `∂w/∂s` содержит `σ'(s)(1+sm)+σ(s)·sm·(1−sm)/τ`. При `s≈0` это `≈ 1/4 + 1/(Nτ)` — **при плоских score'ах запрос почти не управляет вниманием**.

[mini] (стационарный `h`, `|h|=40..60`, 32 слота со случайными ключами):

| Величина | Значение |
|---|---|
| `std(scores)` по позициям | 0.014–0.018 |
| rowmax внимания (L2) | 0.063 (uniform 0.031) — **статическое** предпочтение слота |
| `cos(r_t, r_t')` L2 | **0.9999–1.0000** (iid и smooth h одинаково) |
| `cos(r_t, r_t')` L1 | 1.0000 |
| энтропия внимания | 2.77 из 3.47 max |
| `‖r‖/‖h‖` | 0.163 |
| `τ=0.1` вместо 1.19 | rowmax 0.065 — **не помогает**: sharpening нечего усиливать |

Причина наблюдений: чтение — почти константа, несущая ~0 условной информации о позиции. Плюс `W_k` не обучается: `k_i` — случайный хэш сводки, `h^T W_q^T W_k s_i` не восстанавливает `cos(h, s_i)` (нужна `W_q^T W_k ≈ I`). При 32 слотах правильный матч угадывается с вероятностью ~1/32.

**Следствие:** вопрос «чем запрашивать» вторичен. Пока (i) `W_k/W_v` заморожены, (ii) `std(s)≈0.02`, (iii) нормализация гибридного гейта сглаживает — любая замена `h_t → h̃_{t+1}` ничего не изменит: **выбор слота от запроса не зависит**.

## 3. Задача 1 — предсказательный запрос

### 3.1 Вариант (a): ожидание из головы

```
p_t = softmax(z_t/T_h),  z_t = u_t Cᵀ (+bias)
e_t = Σ_v p_t[v]·E_v = Eᵀ p_t
h̃_{t+1} = φ(e_t),       q_t = W_q h̃_{t+1}
```
- **Градиенты.** Если `p_t` live: `∂CE/∂E` течёт через чтение в embedding-матрицу головы — контур голова→банк→ствол→CE, который доктрина M2 сознательно запрещает. Безопасная форма — `p_t.detach()` (тогда E не учится вообще).
- **Цена.** Полное ожидание: `V×D = 65536×2560 ≈ 1.68e8 MAC/токен` (~0.34 GFLOP) — сопоставимо с 1–3 слоями. **Дешёвый суррогат уже существует**: `h_impl = (σ(u) @ readout)` считается в темперинге — `64×2560 = 1.6e5 MAC` — бесплатно.
- **Идентифицируемость.** При недообученной голове `p_t` близка к маргиналу ⇒ `e_t ≈ const` ⇒ запрос снова константа. Признак: `Var_t(q_t)` и `cos(q_t, q_t')`.
- **Вывод.** (a) имеет смысл только после оживления записи и только в дешёвой форме `h_impl` (detached).

### 3.2 Вариант (b): learned predictor `h̃ = h + P(h)`

```
P: D→D/4→D, last layer zero-init ⇒ P≡0 на старте
q_t = W_q (h_t + P(h_t))
L_pred = 1 − cos(h̃_t, target_t),   target = сводка следующего предложения
```
- **Градиенты.** CE→чтение→q→P и L_pred→P. `target` обязан быть detached.
- **Цена.** `2·D·D/4 ≈ 3.3e6 MAC/токен` (0.0066 GFLOP) — <0.5% слоя.
- **Идентифицируемость.** Внутри предложения `h_t≈h_{t+1}` ⇒ тривиальный оптимум `P→0`. Цель — **сводка следующего предложения**; вырождение проверяется `‖P(h)‖/‖h‖ < 0.01`.

### 3.3 Вариант (c): state + velocity

```
v_t = h_t − h_{t−1},  q_t = W_q(h_t + λ·v_t),  λ init 0
```
- **Цена.** O(D) на токен + кэш `h_{t−1}`; практически ноль.
- **Идентифицируемость.** [mini] при λ=1..3 rowmax меняется на <0.0002: `v` мал относительно `h`, `W_q` гасит разницу. Наивная форма инертна; рабочая — отдельная проекция `q = W_q h + W_v v` и/или нормировка `q`.

### 3.4 Сводка

| | формула | FLOPs/токен | обучение | риск вырождения | ожидание |
|---|---|---|---|---|---|
| (a) head-expectation | `q=W_q Eᵀp` | 1.7e8 (или 1.6e5 через `h_impl`) | в E (live) / никуда (detach) | `p≈unigram ⇒ e≈const` | низкое до фикса записи |
| (b) predictor | `q=W_q(h+P(h))` | 3.3e6 | CE + L_pred в P | `P→0` | среднее, если цель — сводка |
| (c) velocity | `q=W_q(h+λv)` | O(D) | CE в λ/W_v | λ→0; инертно при плоском softmax | низкое |

## 4. Задача 2 — surprise-маршрутизация

**Факт кода:** явного роутера нет; его роль де-факто играет `fusion` (MLP `3D→D→D`), но у него нет давления специализироваться и нет входа «неожиданность»; `_fusion_tau_alpha` zero-init и (по `mem_tau_reg≈0`) не обучается.

```
признаки:  ν_l = 1 − cos(h, r_l);  pen (зеркальный pred-error, detached, 1-шаг);
           λ_lac = max(0, ell_rel−1);  τ_l = τ-лестница слоя
logits:    z_l = a_l·ν_l + b_l·pen + c_l·(1/τ_l) + d_l   (learnable, zero-init)
гейт:      g = softmax(z/T_r)  (или hybrid_gate — единый стиль)
read:      r = Σ_l g_l r_l;   h ← h + scale·r
баланс:    L_bal = L·Σ_l f_l·ḡ_l (Switch-style),  H(g) ≥ H_min
```
- **Обучение.** CE-градиент в a,b,c,d через g; L_bal предотвращает коллапс. Без ручных порогов.
- **Цена.** O(3D) на позицию + softmax — пренебрежимо.
- **Идентифицируемость.** Тривиальный оптимум — «всё в L2»; без L_bal роутер схлопнется. Жёсткий argmax без ST/Gumbel не даёт градиента.
- **Но:** [mini] все `r_l` — почти константы; маршрутизация констант не меняет ничего. **Сначала контентная зависимость чтения, потом роутер.** Промежуточно ценны логи `ν_l, pen, λ_lac`.

## 5. Задача 3 — аудит измерений

### 5.1 `mb_l1_overwrites` растут ~1000/250 шагов (4/шаг)

- Счётчик инкрементируется **на каждой записи**, включая заполнение пустых слотов (`memory_bank.py:139, 278`). `fill_rate` L1 = 1.0 после 3 записей; 4/шаг = число SEP в окне × B (~1 SEP на последовательность при B=2, seq=224). Это **write rate**, не «насыщение»: L1 (3 слота) кольцуется мгновенно, L2 (32) — за 8 шагов; дальше FIFO.
- Полезность перезаписи: при константном чтении почти безвредна и почти бесполезна; [mini] `slot_novelty` для случайных сводок ≈0.94, вытеснение по возрасту.
- Нормально: для потокового кольца растущий счётчик ожидаем. Ненормально: **содержимое не влияет на чтение**.

### 5.2 `mb_l3_births` статичны, `mb_l3_updates` растут

- `mb_l3_*` — это **UCL** (`losses.py:449-452`), не банк. S=8 слотов.
- Update: `_n_updates += 1` на слот с непустой маской (≤8/forward). Рост = каждое предложение-форвард переназначает слоты и подмешивает `α=0.5`. Это running mean.
- Birth: `novel = (1−best_sim) > gap=0.5 & conf ≥ thr`; после консолидации 8 направлений «косинусное расстояние >0.5 до ВСЕХ ключей» почти не случается ⇒ рождения затухают. **Нормальное насыщение при жёсткой ёмкости 8**.
- Согласованность: `+6868 updates` за 250 шагов = 27.5/шаг > 8 — **невозможно** при одном форварде; окно для L3-чисел ≥ ~860 шагов. Числа брифа для L1 и L3, похоже, сняты на разных интервалах.

### 5.3 `mb_scale = −0.963`

- Это `tanh(log_scale)`; `log_scale` init −2.0 ⇒ `tanh(−2) = −0.9640`. Наблюдаемое −0.963 ⇒ `log_scale = −1.9868`, дрейф **+0.0132 за 7315 шагов** (1.8e-6/шаг — на 2–3 порядка ниже lr).
- **Знак не интерпретируется**: `fused` — выход MLP, знакопеременный; смысл имеет `‖scale·fused‖/‖h‖`. [mini] при необученном fusion `‖fused‖/‖h‖ ≈ 0.11`.
- Почему константа: (i) zero-init `fusion[-1]` ⇒ градиенты всего read-пути ровно 0.0; (ii) после выхода из нуля `fused` почти константен, CE-градиент к константному сдвигу мал (поглощается token_bias); (iii) `∂softmax/∂τ ∝ s/τ²`, `s≈0.02` ⇒ τ не двигаются.
- [mini] после искусственного оживления fusion градиенты оживают (`log_scale 3.2e2`, `W_o 5e2`) — путь есть, но «холодный».

### 5.4 `novelty_gate` вырожден

- Вычисление — внутри `@torch.no_grad()` `write`. Результат только пишется в `slot_novelty`/`novelty_mean`. [mini] `grad = None` у всех параметров `novelty_gate`.

### 5.5 Что нормально, что деградация

| Наблюдение | Статус |
|---|---|
| Рост overwrites, fill=1.0, кольцо | норма (потоковый буфер) |
| L3 births → плато, updates растут | норма для S=8, но ёмкость 8 — предел |
| `mb_scale≈init`, `mem_tau_reg≈0` | **деградация**: τ-иерархия не адаптируется |
| `novelty_gate` без градиента | **деградация**: мёртвый код |
| `W_k/W_v` без градиента | **деградация**: запись — случайная замороженная проекция |
| Чтение `cos≈1.0` | **деградация**: банк = bias |
| `reset_cache` не чистит буферы | риск rollback-загрязнения |

## 6. Задача 4 — эффект на CE

1. **Разложение:** `CE = H(x_{t+1}|x_{≤t}) + KL(p_data‖p_model) ≥ H_data`. Так как `H_data ≤ H₁`, `KL ≥ 8.39−7.48 = 0.91` нат. **Модель хуже униграммы на ≥0.91 нат** — это недообучение маргинала, не проблема доступа к контексту.
2. **Верхняя граница вклада памяти.** При seq=224 банк — единственный канал за окно. Потенциал = `H(x|224) − H(x|документ)`. Для русской прозы дальние зависимости (тема, кореференция, повтор лексики) — порядок **0.1–0.3 нат** (оценка, не измерение).
3. **Текущий вклад ≈ 0 условной информации.** `cos(r_t,r_t')≈1` ⇒ чтение — константа; константа меняет только маргинал, который голова параметризует `token_bias`. Согласуется с `conflict`: `cos(h_impl,_mem_dir) ≈ −0.05..0.07` — направления ортогональны: память не согласуется и не конфликтует, она просто не несёт сигнала.
4. **Темперинг.** `logits × 1/(1+0.5χ) = 0.85..0.87` ⇒ эффективная температура ×1.15..1.18. На недообученной голове скорее вредит; эффект по CE 0.005–0.02 нат (знак замеряется абляцией `head_temper=False`).
5. **Ожидания.** Сейчас 0.00–0.05 нат; после оживления чтения — 0.02–0.15 нат; долгосрочный потолок канала 0.1–0.3 нат. Всё меньше 0.91 нат униграммного разрыва — **память не текущее бутылочное горло**.

## 8. Режимы отказа

1. **Ложная селективность.** `τ→0` на плоских score'ах даёт winner-take-all по случайному ключу: чтение станет константой *другого* слота.
2. **Коллапс роутера** на L2/один слот (нет L_bal).
3. **Predictor-identity**: P учится предсказывать сам h — нулевой эффект при положительных затратах.
4. **Градиент из головы в банк**: если (a) не детачить `p_t`, голова и ствол конкурируют (повтор ошибки моста).
5. **Контаминация через общий банк при B=2** — элемент 0 читает документ элемента 1; усилится при селективном чтении.
6. **Rollback-загрязнение**: `reset_cache` не чистит банк — после NaN-отката память хранит «отравленное» содержимое.
7. **Ноутбук без M62-ротации** (исправлено): счётчики кумулятивны, «документная» семантика размывается.
8. **Переоценка CE-выигрыша**: при 0.91 нат униграммного разрыва даже идеальная память не сдвинет headline.

## 9. Минимальный эскиз

- **Шаг 0 (диагностика, 0 обучения).** На замороженном чекпойнте: F1 (константность чтения), F6/F7 (census градиентов), F8 (абляция чтения), F9 (темперинг). Решение «делать/не делать» без тренировки.
- **Шаг 1 (обязательное условие всего).** Оживить запись: `W_k/W_v` — в живой граф (out-of-place `index_copy` по образцу UCL) **или** self-supervised цель `W_k(summary_t) ≈ W_k(h_{t+1})`; нормировать `q` и пересмотреть шкалу score, τ — с внятным приором и живым градиентом.
- **Шаг 2 (c).** `q = W_q h + W_v v`, `v` — EMA дельт, отдельная проекция.
- **Шаг 3 (b).** Residual-predictor `P` с целью «сводка следующего предложения», `L_pred` через LossBalancer.
- **Шаг 4 (a).** `h_impl` (detached) как дополнительный вход `q`.
- **Шаг 5.** Явный surprise-роутер вместо неявного fusion + `L_bal` + логирование `ν_l`.
- Всё — за флагами, A/B на hold-out, откат при `ΔCE ≥ −0.01` нат за ≥3 eval.

## 10. Вердикт

1. **Предсказательный запрос — переформулировать.** В текущей геометрии он не может помочь: чтение — константа, ключи — замороженный случайный хэш, softmax плоский. Сначала шаг 1 (живая запись + нормировка q + шкала score), затем (c), (b), (a) в detached-форме. Ожидаемый эффект после фикса: 0.02–0.15 нат.
2. **Surprise-маршрутизация — не делать сейчас.** Маршрутизировать константы нечего; ценность — в логировании `ν_l/pen/λ_lac`.
3. **Аудит — подтверждён с уточнениями:** novelty-гейт мёртв by construction; `W_k/W_v` не обучаются; чтение вырождено; `mb_scale/log_tau` почти не двигаются; L3-насыщение (8 слотов) нормальное, но ёмкость — предел; числа L1/L3 сняты, похоже, на разных интервалах.
4. **CE-эффект:** потолок канала за окном 224 — 0.1–0.3 нат; текущий вклад ≈ 0; ближайший приоритет — униграммный разрыв 0.91 нат.

**Неопределённость:** (i) mini-прогоны на случайной инициализации `q_proj/W_o` (в живом прогоне они обучались, селективность может быть выше, но `W_k/W_v` заморожены и там); (ii) точный интервал L3-чисел; (iii) причина дрейфа `log_scale` (кандидаты: холодный градиент, потеря моментов Adam на resume).
